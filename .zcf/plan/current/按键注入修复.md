# 修复：点击「识别画面」后切到指定游戏，按键无法自动操作

- 建立时间：2026-10-25 10:55:27
- 方案：A（只修按键注入这一层）
- 状态：已完成

## 根因（实测，不是推测）

探针窗口记录 `WM_KEYDOWN` 的 lParam，跑 `scripts/win32/game-key.ps1`：

| 场景 | 窗口收到 | 脚本回报 |
| --- | --- | --- |
| 修改前 keybd_event(vk, 0, ...) | `WM_KEYDOWN vk=66 sc=0` | `{"ok":true}`（假成功） |
| 修改后 SendInput + MapVirtualKey | `WM_KEYDOWN vk=66 sc=48` | `{"ok":true,"sent":2,"scan":48}` |

扫描码 0 的事件会被按扫描码映射键位的输入路径（Raw Input / DirectInput）丢掉。
`keybd_event` 没有返回值，所以被 UIPI 拦下时也报成功，用户看不到任何报错。

## 影响面

- `sendGameKey` 的调用方只有两处：`/api/ocr/screen/key`、`game-shot.mjs` 的 F2 截图。
- 鸣潮与异环共用同一条按键路径。
- 返回结构只增不改（多了 `scan`、`sent`），老调用方不受影响。

## 遗留（不在方案 A 范围内）

1. `/api/ocr/screen/focus` 不校验 flow id，任何页面都能把任意游戏窗口拉到前台。
2. 前端 `ocrOk` 只在挂载时取一次，引擎刚装好时要刷新页面才能识别。
3. `profileForGame()` 对没配 profile 的游戏静默回退到鸣潮。
