# 识别画面：按键根本送不进游戏（UIPI）

- 时间：2026-10-27_211330
- 承接：2026-10-27_203847识别画面失败可诊断.md（那份解决「认不出来时看不见原因」，这份解决「按键根本到不了游戏」）

## 根因（实测，不是推断）

鸣潮以**管理员身份**运行（`target_elevated=true`），本程序是普通权限（`self_elevated=false`）。
Windows 的 UIPI 不允许低完整性进程向高完整性窗口投递输入：

| 手段 | 实测表现 |
| --- | --- |
| SetForegroundWindow | 成功 —— 窗口能切到前台，焦点也确实拿到了 |
| SendInput | **返回成功，按键被静默丢掉** —— 游戏根本没收到 |
| PostMessage(B) | 直接返回 False（UIPI 拒绝） |

所以：窗口切过去了、进度条也在走，但背包 / 地图从来没打开；接下来每一帧都认不出，
最后给一句误导的「还差体力」。这就是用户勾的 B（窗口切过去了但背包没开）。

## 修法

| # | 改动 | 作用 |
| --- | --- | --- |
| S11 | `scripts/win32/xfc-input-probe.cs` + `check-input.ps1` | 读双方进程 token 的提权状态（TokenElevation） |
| S12 | `game-window.mjs` 的 `checkInputChannel()` | focus 成功后验一次；同一窗口只查一次（编译 C# 要一秒多） |
| S13 | `resource-field.jsx` | `input_ready === false` 就停：不按 B、不空转，直接说怎么修 |
| S14 | README 第 7 条 | 两条修法：管理员运行本程序，或让游戏以普通权限启动 |

**判据为什么不用 PostMessage(WM_NULL)**：它恰好在 UIPI 的放行名单里 ——
实测 `post_ok=true`，可真实的 B 键投递是 `False`。拿它当判据会放过这个 bug。
改成比双方的提权状态，才是 UIPI 的实际规则。

探测本身失败（脚本没起来 / 超时）时**不阻断**流程：宁可像以前一样在按键那步报错，
也不能因为一个辅助检查把能用的功能挡死。

## 验收

| 项 | 结果 |
| --- | --- |
| npm run check | 668 项 / 0 失败 + 构建成功（新增 3 条源码守门） |

## 用户要做的

游戏和本程序的**权限一致**就行：右键本程序「以管理员身份运行」，或者让游戏以普通权限启动。
