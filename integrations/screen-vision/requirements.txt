# Python 视觉后端（屏幕识别）的依赖。
#
# 装哪儿：设置 → 屏幕识别 → Python 视觉后端 → 「一键安装依赖」，
# 它会建 data/vision-venv 这个项目内虚拟环境再装到这里列的东西，
# 不动你系统里的 Python。也可以自己来：
#   python -m venv data\vision-venv
#   data\vision-venv\Scripts\python.exe -m pip install -r integrations\screen-vision\requirements.txt
#
# 为什么是 RapidOCR(ONNX) 而不是 PaddlePaddle：
#   · 用的是同一套 PP-OCR 模型（本仓 tools/ocr/rapidocr/models 里已经有现成的 onnx）；
#   · onnxruntime 的 wheel 小得多，Python 3.13/3.14 上也有；
#   · 不需要 AVX 也能跑，老机器不至于直接罢工。
#
# 支持的 Python 版本：**3.10 ~ 3.14**（win_amd64）。
#   3.15 目前装不上：onnxruntime 还没发 cp315 的轮子，pip 只能现编，而现编
#   要 C++ 工具链。程序会在选解释器那一步就明确拦下来，不再让你走到 pip 报错。
#   这份范围是**实测出来的**，不是猜的：node scripts\vision-python-matrix.mjs
#   会去 PyPI 把每个包的 win_amd64 轮子按 cpXX 打一张表，交集就是上面这个范围；
#   加 --check 还能断言「声明的范围」和「事实」一致，onnxruntime 哪天发了
#   cp315，那条断言会红，提醒把范围扩上去。
#
# 注意：rapidocr 3.x 不把 onnxruntime 写进必装依赖（它支持多种后端），
# 所以这里必须显式列出来，漏了就是「装完了但一跑就 ImportError」。

rapidocr>=3.9,<4
# 为什么是 >=1.20,<2 而不是钉死一个版本：
#   onnxruntime 每个大版本的轮子覆盖范围都不一样，而 **cp314（3.14）只有
#   1.24.1 之后才有轮子**、**cp310（3.10）到 1.24 就没了**。所以两头都要容：
#   3.10 上会落到 1.23.x，3.14 上会落到 1.24+。写死任何一头都会让另一端
#   掉进「没有匹配的轮子 → 源码编译 → 用户机器上没有工具链 → 装依赖失败」。
#   改这个区间之前，先跑一遍 scripts\vision-python-matrix.mjs。
onnxruntime>=1.20,<2

# 下面这几个 rapidocr 自己也会拉，但显式写出来是为了两件事：
#   1. 版本下限说清楚（numpy 2 的 API、opencv 的 matchTemplate 口径）；
#   2. 万一以后 rapidocr 改了依赖树，这里不会悄悄少东西。
numpy>=2.0
opencv-python>=4.10
pillow>=10
