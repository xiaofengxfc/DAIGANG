# DESIGN.md

> **第 3 版 · 纯白扁平**
> 第 1 版「夜班帐桌」：石墨底 + 靛蓝 + 栏线，深色为默认。
> 第 2 版「白玻璃」：白色 + 毛玻璃 + 柔光层。
> **这一版推翻第 2 版**：白玻璃的柔光和模糊，在「一个人盯十几单」的场景里
> 是纯负担——模糊把边界吃掉，柔光让白不够白，两者都在抢本该留给数字的注意力。
> 现在只剩**白、黑、一条细线**。
>
> 被推翻的只有外观。业务结构（账簿抬头、状态词汇、右对齐金额、全部断点）
> 原样保留。样式仍然是「旧样式 + 结尾覆盖层」，所以回退 = 删掉覆盖层最后两段。

## 方向契约

**THESIS** — 这个世界叫「白纸帐台」：一张干净的白纸，一支黑笔，
几条铅笔画的分栏线。它拒绝的品类有三个：第 2 版的自己（柔光 + 毛玻璃，
看久了像云里雾里）、第 1 版的自己（深色石墨，夜里像机房），
以及"到处描边、处处是卡片"的通用后台。

代肝这一行的真相不是"炫"，是**一个人同时盯着十几单、每一分钱都要对得上**。
所以这一版做的每一件事都指向同一件事：**让数字和名字自己站住，
线只用来分开区域，绝不用来装饰。**

**OWN-WORLD** — 画布是纯白（`#FFFFFF`），深色版是近黑（`#111214`）。
面与面之间**只靠一条 1px 中性灰线**分开（`--line`），没有阴影、没有模糊、
没有半透明叠加。文本三档灰：`#111214` / `#4B5058` / `#6B7280`。
靛蓝是唯一强调色，只出现在主按钮、选中态、链接；状态色只染小圆点和小标签。

金额一律右对齐、等宽、表格数字（tabular-nums）—— 这条从第 1 版继承，不动。

全部内容清空后仍然认得出：**纯白底 + 细线分栏 + 靛蓝主按钮 + 右对齐数字**。

**STORY** — 打开就看到"今天台面上有什么"：待确认/待付款/进行中/待验收四栏实数，
以及今日应收、已收、尾款。点进去能改价、看客户的单、看进度、取密码。
离开时相信两件事：钱算得对，密码存得住。

**FIRST VIEWPORT** — 桌面：左侧导航轨（白底，右边一条细线）+ 顶栏（页名、全局搜索、刷新、主操作）。
内容区第一屏是**账簿抬头**——一块带细线的面，列出四类待办计数与三个金额，
数字右对齐；其下直接是「进行中调度列表」，每单一行。
手机：顶栏 + 底部标签，抬头折成两行，调度列表铺满。

**FORM** — 现代运营工作区。画像取自 CRM 的清晰层级和代肝业务的状态调度。
本次未跑概念种子脚本、未出合成稿（本机无图像生成能力），以完整落地优先——
这是对完整流程的一次压缩，已如实披露。

## 颜色策略

**Restrained**：中性白 + 单一强调色（靛蓝）。状态色是 Operate 模式必需的语义词汇，
但**只染文字和小圆点，不铺整块底**——第 1 版满屏色块，正是"花"的来源。

### 场景定明暗

白天站着用手机、晚上在书桌前。**浅色（纯白）是默认，深色是同一套结构在暗处的版本**，
由侧栏底部的图标按钮切换，存在 `localStorage` 的 `xfc.theme`。

### 浅色（默认）

| Token | 值 | 用途 |
| --- | --- | --- |
| `--bg` | `#FFFFFF` | 画布最底，同时也是面板底色（写在 `html` 上） |
| `--surface` / `--surface-solid` | `#FFFFFF` | 面板、表头、抽屉 |
| `--surface-inset` | `#F7F8FA` | 输入框、代码块（**唯一**比白略深的常规底） |
| `--line` | `#E6E8EC` | 结构线，1px，**这是唯一的分层手段** |
| `--line-strong` | `#D6D9DF` | 分组分隔、输入框描边 |
| `--ink` / `--ink-2` / `--ink-3` | `#111214` / `#4B5058` / `#6B7280` | 主 / 次 / 弱，对白底 18.9 / 8.2 / 5.0 : 1 |
| `--cinnabar` | `#4F46E5` | 唯一强调色（保留旧变量名，兼容现有组件） |
| `--jade` / `--amber` / `--slate` / `--oxblood` | `#0F7A52` / `#96620F` / `#2F6BA8` / `#B03A5B` | 状态语义，只给小圆点和小标签 |

深色把同一组名字换一套值（`--bg` 变成 `#111214`，`--line` 变成 `#26282D`，
强调色提亮一档），**结构完全不变**。深色下不再有任何半透明叠加。

### 三级灰都必须过 WCAG 4.5:1

第 1 版的 `--ink-3` 是 `#8d97a6`，对白底只有 **2.6:1**——服务说明、时间戳
这类"真内容"根本读不清。现在三级灰是 18.9 / 8.2 / 5.0。
`--ink-3` 只给占位和装饰（`::placeholder`、"暂无说明"），真内容用 `--ink-2`。

**`--ink-3` 在浅色下是 5.0:1，这是刻意卡在 4.5 之上的一点点余量**——
它给占位符用，而占位符也是文字，也该读得出来。

## 扁平规则（这一版的核心，只有一条）

> **没有任何元素可以模糊背后的东西。`backdrop-filter` 全仓为 0。**

第 2 版那套「只有压在画布上的面才配模糊」的规则**整条作废**。
现在是更简单的一条：谁都不配。

具体到代码：`--glass-blur` 设为 `0px`，于是既有的 18 处
`backdrop-filter: blur(var(--glass-blur))` 全部自动失效，
加上覆盖层对抽屉/弹窗显式写 `backdrop-filter: none`。

**分层靠三样东西，按优先级：**

1. **一条 1px 的 `--line` 细线**（首选）。侧栏右缘、面板边界、表格行间、分组之间。
2. **一块 `--surface-inset` 极浅灰底**（次选）。只给输入框和代码块——
   因为它们需要"这是可以输入的"这个信号，而这个信号白底给不了。
3. **留白**（默认）。能不画线就不画。

**阴影只给浮层**：抽屉、对话框、下拉结果面板、吐司。它们真的浮在内容之上，
必须和背景断开，所以允许 `--shadow-pop` / `--shadow-drawer`。
页面内的面**一律无阴影**——白底 + 细线已经够了，再加影子就回到第 2 版。

### 没有柔光层了

第 2 版的 `body::before` 四团径向渐变**已停用**（`content: none`）。
它存在的唯一理由是"给毛玻璃提供可透的东西"；毛玻璃没了，它就成了
一块没有理由的脏。

配这条时踩过的坑仍然记在这里：底色**必须写在 `html` 上，`body` 保持
`transparent`**。`body` 的背景会向上传播成画布背景、画在 `z-index:-1`
的伪元素下面。这一版虽然不再需要柔光，但如果以后有人要加回任何
`position: fixed; z-index: -1` 的底层装饰，这个坑依然成立。

## 字体

Operate 面，工作字体即可，**不做展示字体搭配**。
中文走系统栈，金额/单号/日期/账号走等宽——这是"数据与度量"的正当用法。

```
--font-ui: -apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", "Noto Sans SC", sans-serif
--font-fig: ui-monospace, "SF Mono", "Cascadia Mono", Consolas, "DejaVu Sans Mono", monospace
```

字号固定 rem 阶：`11 / 12 / 13 / 14 / 16 / 19 / 23 / 28px`。行高：正文 1.6，紧凑 UI 1.35。
标题 `letter-spacing: -0.02em`（不越过 -0.04em）。

**正文最小 10px，内容文字最小 11px。** 9px 在 Windows 上已经糊了。

## 布局

- 断点：`≥1080px` 桌面（左轨 236px + 内容）· `720–1080` 收窄轨 · `<720` 手机（底标签 + 全宽）。
- 响应式是**结构性的**（换导航、表格转卡片行），不是把字号缩小。
- 密度：表格行高 40px（手机 52px）。圆角：面板 12px，控件 10px，药丸只给小组件。
- 间距阶：4 / 8 / 12 / 16 / 24 / 32 / 48。

## 组件

- **面**：`1px solid var(--line)` + 12px 圆角，白底，**无阴影**。分组靠留白，不靠线。
- **栏目线表格**：无外框，行间发丝线；表头白底 + 下边线。
- **状态灯**：6px 圆点 + 文字，不靠颜色单独表意。
- **封条（锁定态）**：只有保险箱用。
- **抽屉**：右侧滑出，`<dialog>` 承载，左边一条细线，白底。
- **空态**：教你怎么用，不是"暂无数据"。虚线框，表示"这里还没有东西"。
- **提示条**（`.note`）：白底 + 细线，左边一条 3px 语义色条。

## 运动

克制。150–260ms，`cubic-bezier(.2,.7,.3,1)`。**只表达状态**：

- 换页：内容区轻微上浮 6px + 淡入（`rise-in`），每次挂载一次。
- 悬停：列表行转 `--surface-inset` 浅灰；按钮加深一档。
- 按下：`scale(.975)`。

不做整页入场编排、不做数字滚动、**不做常驻动效**（第 2 版的柔光漂移已删除）。
`prefers-reduced-motion: reduce` 下全部关掉。

## 禁止

- **`backdrop-filter`**（除 0px 之外的一切模糊）。这是这一版最容易被自己破坏的规则。
- **页面内的阴影**。阴影只给浮层（抽屉、弹窗、下拉、吐司）。
- **半透明叠加**。所有面都是实色，`rgba` 只用于线和浮层遮罩。
- 发光边缘、霓虹强调、渐变文字。
- 卡片彩色左边框；零偏移彩色光晕。
- **整块铺色的状态标签**——状态色只染字和小圆点。
- 页面抬头压一行小标签（`eyebrow`）。它和下面的 h2 说的是同一件事，
  是"颜色太杂"的主要来源，本版已从 10 个页面抬头全部移除。
- 仪表盘"大数字 + 小标签"英雄指标模板——第一屏是账簿抬头。
- 装饰性动效；模态框当第一反应（优先内联与抽屉）。

## 构建之后确定下来的补充规则

上面是动手前的契约，下面是代码落地时被真实渲染逼出来的规则，一并算数。

### 旧皮 + 覆盖层，而不是重写

`tokens.css` / `base.css` 是重写的，`app.css`（3300 行）和
`client/styles.css`（3500 行）**保留原样，在末尾追加「纯白扁平覆盖层」**。
好处是回退只删一段、diff 干净、旧规则里的响应式细节不用重新推一遍。
代价是同一组选择器出现两次——所以覆盖层里每一段都写了「为什么」。

顺带说得清一件事：**旧样式里那 18 处 `backdrop-filter` 一处都没删。**
扁平化靠的是把 `--glass-blur` 设成 `0px`，让 `blur(calc(0px * n))` 全部归零。
这样 diff 里看不到 18 处删除，回退也只是改一个令牌值。
真正的删除是留给下一次大扫除的。

### 价格表是「一张纸」，不是一摞卡片

价格表被刻意拍平成 sections：`.price-group` / `.price-workspace` / `.price-category`
全部 `border: 0; background: transparent`，靠细线分区。
拍平那一段把 `padding-inline` 归零过，外层重新成纸之后要把内边距还给内容。

自检里那条「整页没有毛玻璃」守着它：只要这三层里任何一层偷偷加了
`backdrop-filter`，就说明覆盖层又被写成玻璃了。

### 服务名不该比价格小

价格表里服务名原本 11px、金额 14px，读起来像"数字才是主角、名字只是注解"。
现在 13px / 14px，小标签 10px。

### 价格表的断点必须按"列最小宽"算出来，不能拍脑袋

账目行是 5 列固定最小宽的网格：**列最小宽合计 677px + 4×12 间距 = 725px**。
再算上目录轨 190、目录内边距 36、内容区内边距 68、侧栏 236 ——
**视口要有约 1255px 才放得下。**

原来的折行断点设在 760px，于是 760–1255px 这 500px 宽的区间里，
行内容比行本身宽 159–334px。而 `.react-main` 有 `overflow-x: clip`，
**不会出滚动条，右侧的「价格」和「操作」被静默裁掉**——
不出报错、不出滚动条，肉眼扫一眼也看不出来，是最难发现的一类坏。

现在账目表只在 **≥1280px** 出现，以下一律走卡片行（复用移动端那套，已测过）。
另外给 `.price-catalog` 加了 `overflow-x: auto` 当保险丝：
万一以后有人调宽了列，让它出滚动条，而不是被裁掉。

**凡是"内容宽度由列最小宽决定"的表格，都要用这个算法反推断点**，
不能沿用别处的 760 / 980。`scripts/checks/glass-check.mjs` 里有一条
7 种宽度的探测守着它（量 `row.scrollWidth > row.clientWidth` 和
最后一列右缘是否越过容器）。

### 账簿抬头的两条形态

- **桌面**：一格一个指标，标签在上、数字在下、数字右对齐。
- **手机（≤860px）**：格子改成一行一个指标（标签左、数字右），两列网格。
- 抬头里那条「本月已收 · 利润」在窄屏上 `flex-basis: 100%` 独占一行。
  **不加这条，整页会被它撑出横向滚动。**

### 手机上的表格

栏目线表格在 ≤720px 折成卡片行（`data-label` 当行标签）。
折完之后次要列不再有意义，用 `.col-opt` 整列隐藏。

### 底部标签由 JS 决定，不靠 CSS 开关

底部标签只在 `matchMedia('(max-width: 860px)')` 为真时才建进 DOM。
理由：移动端导航不该在桌面端留一个隐藏的空壳。

### `[hidden]` 必须压得住组件自己的 display

`.note` 一类组件自带 `display: flex`，会盖过浏览器默认的 `[hidden] { display: none }`。
基础层里统一加：

```css
[hidden] { display: none !important; }
```

### `replaceChildren` 的空值陷阱

`el.replaceChildren(null)` 会插入一个内容为 `"null"` 的文字节点（和 `appendChild` 不同）。
导航角标的条件渲染必须先过滤空值再展开。

### 主题要在模块加载时就写上去

`data-theme` 只在 `Shell` 里设的话，登录页会先用默认色渲染一遍，
登录成功才切过去，中间闪一下。所以 `main.jsx` 在模块作用域就调一次
`applyTheme(readTheme())`。

### 兜底

`.main` / `.react-main` 加 `overflow-x: clip`，任何一页都不该把整页撑出横向滚动。
这是兜底，不是解法——真出现撑宽，先去找那个 min-content 过大的元素。

## 怎么验

外观改动的验收不能靠肉眼扫一眼，两套自动化：

```bash
npm run test:ui                      # 582 项真浏览器交互断言（功能不回归）
node scripts/checks/glass-check.mjs  # 91 项外观断言 + 截图到 shots/glass/
```

`glass-check.mjs`（名字是历史遗留，现在验的是扁平契约）做几件肉眼做不到的事：

1. **像素级证明画布是平的。** 把截图当 data URL 塞回页面、画进 canvas、
   读 `getImageData`，在主内容左侧排水沟取 4 个点——它们必须**完全相同**。
   只要有渐变或光斑残留，这 4 个点就会有差。
2. **证明侧栏没有偷偷叠半透明底。** 对比同高度「侧栏」与「画布」的像素，必须**没有差**；
   侧栏和内容区的分界靠那条 1px 线，不靠色差。
3. **证明没有任何毛玻璃**（含抽屉、弹窗、登录卡片，以及价格表那三层）。
4. **证明没有嵌套卡片**，以及对比度、字号、列宽、横向溢出、窄屏。

这四条都是第 2 版那条断言的**反面**。它们不是被删掉而是取了反：
扁平化最典型的做坏方式就是某处漏了一处 `backdrop-filter`、一处渐变底，
肉眼在截图里看不出来，只能靠断言抓。

改外观之前先跑一遍，改完再跑一遍。
