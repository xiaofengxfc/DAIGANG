# DESIGN.md

> **第 2 版 · 白玻璃**
> 第 1 版是「夜班帐桌」：石墨底 + 靛蓝 + 栏线分层，深色为默认，
> 并在文末明令禁止玻璃拟态。这一版推翻它：**白色 + 毛玻璃 + 克制动效**。
> 被推翻的只有外观，业务结构（账簿抬头、状态词汇、右对齐金额）原样保留。
> 旧的样式代码没有删，全部留在文件前半段；新外观是文件末尾的
> 「白玻璃覆盖层」，回退只需删掉那一段。

## 方向契约

**THESIS** — 这个世界叫「白玻璃工作台」：一张铺在柔光上的白色台面，
上面浮着几块磨砂玻璃。它拒绝的品类有两个：一个是上一版的自己
（深色石墨 + 栏线，夜里看着像机房），另一个是"到处描边、处处是卡片"的通用后台。

代肝这一行的真相不是"炫"，是**一个人同时盯着十几单、每一分钱都要对得上**。
所以这一版做的每一件事都指向同一件事：**让数字和名字自己浮出来，别用线和颜色去框它们。**

**OWN-WORLD** — 画布是极淡的冷白（`#eef1f7`）加四团柔光；
内容是一层半透明白玻璃（`backdrop-filter`）；玻璃靠
「一层很淡的落地影 + 一条内高光顶边」浮起来，**不靠描边**。
靛蓝是唯一强调色，状态色只以小圆点和小标签的形式出现。
金额一律右对齐、等宽、表格数字（tabular-nums）—— 这条从第 1 版继承，不动。

全部内容清空后仍然认得出：**白玻璃 + 柔光 + 靛蓝 + 右对齐数字**。

**STORY** — 打开就看到"今天台面上有什么"：待确认/待付款/进行中/待验收四栏实数，
以及今日应收、已收、尾款。点进去能改价、看客户的单、看进度、取密码。
离开时相信两件事：钱算得对，密码存得住。

**FIRST VIEWPORT** — 桌面：左侧玻璃导航轨 + 顶栏（页名、全局搜索、刷新、主操作）。
内容区第一屏是**账簿抬头**——一块厚玻璃，列出四类待办计数与三个金额，
数字右对齐；其下直接是「进行中调度列表」，每单一行。
手机：顶栏 + 底部玻璃标签，抬头折成两行，调度列表铺满。

**FORM** — 现代运营工作区。画像取自 CRM 的清晰层级和代肝业务的状态调度。
本次未跑概念种子脚本、未出合成稿（本机无图像生成能力），以完整落地优先——
这是对完整流程的一次压缩，已如实披露。

## 颜色策略

**Restrained**：中性白 + 单一强调色（靛蓝）。状态色是 Operate 模式必需的语义词汇，
但**只染文字和小圆点，不铺整块底**——第 1 版满屏色块，正是"花"的来源。

### 场景定明暗

白天站着用手机、晚上在书桌前。**浅色（白玻璃）是默认，深色是同一套玻璃在暗处的版本**，
由侧栏底部的图标按钮切换，存在 `localStorage` 的 `xfc.theme`。

### 浅色（默认）

| Token | 值 | 用途 |
| --- | --- | --- |
| `--bg` | `#EEF1F7` | 画布最底（写在 `html` 上，不是 `body`） |
| `--glow-a/b/c/d` | 靛蓝 / 天蓝 / 粉 / 青，alpha 0.16–0.26 | 四团柔光，毛玻璃唯一的"透出物" |
| `--glass` | `rgba(255,255,255,.60)` | 常规玻璃面 |
| `--glass-strong` | `rgba(255,255,255,.78)` | 顶栏、抽屉、弹窗、账簿抬头 |
| `--glass-soft` | `rgba(255,255,255,.40)` | 玻璃**里面**的浅底（表头、目录轨、空态） |
| `--glass-inset` | `rgba(255,255,255,.66)` | 输入框、代码块 |
| `--line` | `rgba(16,24,40,.07)` | 结构线，刻意几乎看不见 |
| `--line-strong` | `rgba(16,24,40,.13)` | 分组分隔 |
| `--ink` / `--ink-2` / `--ink-3` | `#10141C` / `#4D5766` / `#636D7C` | 主 / 次 / 弱，对白底 16.3 / 6.5 / 4.6 : 1 |
| `--cinnabar` | `#5B5BD6` | 唯一强调色（保留旧变量名，兼容现有组件） |
| `--jade` / `--amber` / `--slate` / `--oxblood` | `#1F9D6B` / `#B8791A` / `#3F7FBD` / `#C05070` | 状态语义，只给小圆点和小标签 |

深色把同一组名字换一套值（`--glass` 变成 `rgba(30,35,48,.6)`，
柔光提亮一档，强调色提亮一档），**结构完全不变**。

### 三级灰都必须过 WCAG 4.5:1

第 1 版的 `--ink-3` 是 `#8d97a6`，对白底只有 **2.6:1**——服务说明、时间戳
这类"真内容"根本读不清。现在三级灰是 16.3 / 6.5 / 4.6。
`--ink-3` 只给占位和装饰（`::placeholder`、"暂无说明"），真内容用 `--ink-2`。

## 玻璃规则（这一版的核心，只有一条）

> **只有直接压在画布上的面，才配 `backdrop-filter`。**

具体是两组：

- **压在画布上**：侧栏、顶栏、手机底部标签、页面级面板（`.panel` / `.ledger` /
  `.orders-panel` / `.price-group` …）、登录卡片。
- **浮在所有东西之上**：抽屉、对话框、吐司、下拉结果面板、过期提示条。
  它们必须自己模糊一次才压得住底下的内容。

**其余一律不给模糊**，只给半透明底 + 内高光：按钮、提示条、空态、表头、
安装面板、价目表、服务选择器……

两个理由，都踩过：

1. **玻璃叠玻璃会把内层糊成实心。** 一层 60% 白再叠一层 60% 白 ≈ 84% 白，
   质感没了，还正好犯了「禁止嵌套卡片」。
2. **内层背后已经是一张模糊过的面，再模糊一次纯属白花钱。**
   一个 34px 的按钮做 `backdrop-filter`，GPU 开销是真的，视觉收益是零。

`scripts/checks/glass-check.mjs` 里有一条「玻璃不得嵌套」的断言守着它（叠加层除外）。

### 柔光层是玻璃的前提，不是装饰

纯白平背景上 `backdrop-filter` **什么都看不出来**——没有东西可透。
所以画布必须垫一层柔光：

```css
body::before {
  position: fixed; inset: -12vmax; z-index: -1; pointer-events: none;
  background: radial-gradient(...) ×4;
  animation: glow-drift 34s var(--ease) infinite alternate;
}
```

配这条规则时有个坑：**底色必须写在 `html` 上，`body` 保持 `transparent`。**
`body` 的背景会向上传播成画布背景、画在 `z-index:-1` 的伪元素**下面**，
那样柔光就被盖住，玻璃也就成了死白。

柔光层 `pointer-events: none` 且 `position: fixed`——不参与布局，不吃点击。

## 字体

Operate 面，工作字体即可，**不做展示字体搭配**。
中文走系统栈，金额/单号/日期/账号走等宽——这是"数据与度量"的正当用法。

```
--font-ui: -apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", "Noto Sans SC", sans-serif
--font-fig: ui-monospace, "SF Mono", "Cascadia Mono", Consolas, "DejaVu Sans Mono", monospace
```

字号固定 rem 阶：`11 / 12 / 13 / 14 / 16 / 19 / 23 / 28px`。行高：正文 1.6，紧凑 UI 1.35。
标题 `letter-spacing: -0.02em`（不越过 -0.04em）。

**正文最小 10px，内容文字最小 11px。** 9px 在 Windows 上已经糊了。

## 布局

- 断点：`≥1080px` 桌面（左轨 236px + 内容）· `720–1080` 收窄轨 · `<720` 手机（底标签 + 全宽）。
- 响应式是**结构性的**（换导航、表格转卡片行），不是把字号缩小。
- 密度：表格行高 40px（手机 52px）。圆角：玻璃面 16px，控件 10px，药丸只给小组件。
- 间距阶：4 / 8 / 12 / 16 / 24 / 32 / 48。

## 组件

- **玻璃面板**：无描边，靠阴影 + 内高光浮起。分组靠留白，不靠线。
- **栏目线表格**：无外框，行间发丝线；表头用 `--surface-solid`（**必须实心**，
  玻璃放在滚动内容上方会透出字）。
- **状态灯**：6px 圆点 + 文字，不靠颜色单独表意。
- **封条（锁定态）**：只有保险箱用。
- **抽屉**：右侧滑出，`<dialog>` 承载。
- **空态**：教你怎么用，不是"暂无数据"。

## 运动

克制。150–260ms，`cubic-bezier(.2,.7,.3,1)`。**只表达状态**：

- 换页：内容区轻微上浮 6px + 淡入（`rise-in`），每次挂载一次。
- 悬停：列表行露一层薄玻璃；按钮变实一档。
- 按下：`scale(.975)`。
- 柔光：34s 极慢漂移，常驻但几乎察觉不到。

不做整页入场编排、不做数字滚动。`prefers-reduced-motion: reduce` 下全部关掉。

## 禁止

- **玻璃嵌套**（见上）。这是这一版最容易被自己破坏的规则。
- 发光边缘、霓虹强调、渐变文字。
- 卡片彩色左边框；零偏移彩色光晕。
- **整块铺色的状态标签**——状态色只染字和小圆点。
- 页面抬头压一行小标签（`eyebrow`）。它和下面的 h2 说的是同一件事，
  是"颜色太杂"的主要来源，本版已从 10 个页面抬头全部移除。
- 仪表盘"大数字 + 小标签"英雄指标模板——第一屏是账簿抬头。
- 装饰性动效；模态框当第一反应（优先内联与抽屉）。

## 构建之后确定下来的补充规则

上面是动手前的契约，下面是代码落地时被真实渲染逼出来的规则，一并算数。

### 旧皮 + 覆盖层，而不是重写

`tokens.css` / `base.css` 是重写的，`app.css`（3300 行）和
`client/styles.css`（3500 行）**保留原样，在末尾追加「白玻璃覆盖层」**。
好处是回退只删一段、diff 干净、旧规则里的响应式细节不用重新推一遍。
代价是同一组选择器出现两次——所以覆盖层里每一段都写了「为什么」。

### 价格表是「一张纸」，不是一摞卡片

价格表被刻意拍平成 sections：`.price-group` / `.price-workspace` / `.price-category`
全部 `border: 0; background: transparent`，靠细线分区。
覆盖层一开始把这三层都做成了玻璃 → **三层嵌套**，被自检抓出来。
现在**玻璃只给最外层 `.price-group`**，里面保持平坦；
拍平那一段把 `padding-inline` 归零过，外层重新成纸之后要把内边距还给内容。

### 服务名不该比价格小

价格表里服务名原本 11px、金额 14px，读起来像"数字才是主角、名字只是注解"。
现在 13px / 14px，小标签 10px。

### 价格表的断点必须按"列最小宽"算出来，不能拍脑袋

账目行是 5 列固定最小宽的网格：**列最小宽合计 677px + 4×12 间距 = 725px**。
再算上目录轨 190、目录内边距 36、内容区内边距 68、侧栏 236 ——
**视口要有约 1255px 才放得下。**

原来的折行断点设在 760px，于是 760–1255px 这 500px 宽的区间里，
行内容比行本身宽 159–334px。而 `.react-main` 有 `overflow-x: clip`，
**不会出滚动条，右侧的「价格」和「操作」被静默裁掉**——
不出报错、不出滚动条，肉眼扫一眼也看不出来，是最难发现的一类坏。

现在账目表只在 **≥1280px** 出现，以下一律走卡片行（复用移动端那套，已测过）。
另外给 `.price-catalog` 加了 `overflow-x: auto` 当保险丝：
万一以后有人调宽了列，让它出滚动条，而不是被裁掉。

**凡是"内容宽度由列最小宽决定"的表格，都要用这个算法反推断点**，
不能沿用别处的 760 / 980。`scripts/checks/glass-check.mjs` 里有一条
7 种宽度的探测守着它（量 `row.scrollWidth > row.clientWidth` 和
最后一列右缘是否越过容器）。

### 账簿抬头的两条形态

- **桌面**：一格一个指标，标签在上、数字在下、数字右对齐。
- **手机（≤860px）**：格子改成一行一个指标（标签左、数字右），两列网格。
- 抬头里那条「本月已收 · 利润」在窄屏上 `flex-basis: 100%` 独占一行。
  **不加这条，整页会被它撑出横向滚动。**

### 手机上的表格

栏目线表格在 ≤720px 折成卡片行（`data-label` 当行标签）。
折完之后次要列不再有意义，用 `.col-opt` 整列隐藏。

### 底部标签由 JS 决定，不靠 CSS 开关

底部标签只在 `matchMedia('(max-width: 860px)')` 为真时才建进 DOM。
理由：移动端导航不该在桌面端留一个隐藏的空壳。

### `[hidden]` 必须压得住组件自己的 display

`.note` 一类组件自带 `display: flex`，会盖过浏览器默认的 `[hidden] { display: none }`。
基础层里统一加：

```css
[hidden] { display: none !important; }
```

### `replaceChildren` 的空值陷阱

`el.replaceChildren(null)` 会插入一个内容为 `"null"` 的文字节点（和 `appendChild` 不同）。
导航角标的条件渲染必须先过滤空值再展开。

### 主题要在模块加载时就写上去

`data-theme` 只在 `Shell` 里设的话，登录页会先用默认色渲染一遍，
登录成功才切过去，中间闪一下。所以 `main.jsx` 在模块作用域就调一次
`applyTheme(readTheme())`。

### 兜底

`.main` / `.react-main` 加 `overflow-x: clip`，任何一页都不该把整页撑出横向滚动。
这是兜底，不是解法——真出现撑宽，先去找那个 min-content 过大的元素。

## 怎么验

外观改动的验收不能靠肉眼扫一眼，两套自动化：

```bash
npm run test:ui              # 483 项真浏览器交互断言（功能不回归）
node scripts/checks/glass-check.mjs # 94 项外观断言 + 截图到 shots/glass/
```

`glass-check.mjs` 做三件肉眼做不到的事：

1. **像素级证明柔光真的画出来了。** 把截图当 data URL 塞回页面、画进 canvas、
   读 `getImageData`，在主内容左侧排水沟取 4 个点——如果柔光被底色盖住，
   这几个点会完全相同。
2. **证明玻璃真的在透。** 对比同高度「侧栏」与「画布」的像素，必须有差。
3. **证明玻璃没有嵌套**，以及对比度、字号、列宽、横向溢出、窄屏。

改外观之前先跑一遍，改完再跑一遍。
