# 代肝价格查询 · 私用运营台

一个**单人自用**的代肝管理后台。不是商城，没有客户注册登录，没有多代肝入驻。
打开就是七个模块：游戏 → 服务与价格 → 客户 → 登录凭证保险箱 → 订单 → 进度记录 → 财务，
外加一个「报价单生成」。

后端继续使用 Node.js 原生 HTTP + SQLite，前端改为 React 19 + Vite 8，图标使用来自 GitHub 的 Lucide React。
业务数据和登录凭证仍全部存在你这台电脑上，依赖只用于构建前端，不参与数据托管。

---

## 一、跑起来

需要 **Node.js 22.12 或更高版本**（用到了内置的 `node:sqlite` 和 Vite 8 构建链）。
没装的话去 <https://nodejs.org> 下载 LTS 版本，一路下一步即可。

从源码运行时先安装依赖并构建一次：

```bash
npm run setup
```

日常开发可以开两个终端：`npm run dev`（前端热更新）和 `npm run local`（本地后端）。

| 系统 | 怎么做 |
| --- | --- |
| Windows | 双击 **`DaiganLauncher.exe`** |
| Windows（只给本机用） | `DaiganLauncher.exe --local` |
| macOS / Linux | 终端里 `./start.sh`，或 `./start.sh --local` |

启动后窗口里会打印两个网址：

```
本机打开：   http://127.0.0.1:8787
手机打开：   http://192.168.1.7:8787     （手机要和这台电脑连同一个 WiFi）
```

启动器里可以直接启动、停止、重启后台，也可以设置当前用户开机自启动。

端口被占用了就换一个：`DaiganLauncher.exe --port 8888`。

## 二、第一次用，按这个顺序

首次打开会引导你设三样东西：店铺招牌名、登录密码、保险箱密码。

然后建议按顺序录：

1. **价格表 → 新建价格表** —— 一张价格表 = 一个游戏。建的时候顺手把区服填上（逗号分隔），
   想好看还可以传个图标。
2. **在价格表里「新建大类」** —— 日常 / 周常 / 深渊 / 活动 / 材料 / 成就……
3. **在大类里「加服务项」** —— 每日委托、清体力、深渊 12 层……选一种计价方式，填单价。
   **服务项只能挂在大类里**，所以先有大类、再有服务项。
4. **服务项详情 → 阶梯价 / 套餐与增项** —— 数量大的（比如深渊层数）加阶梯价；
   加急、指定角色、不动原石这类做成增项。
5. **客户** —— 录第一个客户，手机号填上（它是客户的标识，以后直接搜手机号）。
6. **订单 → 开新单** —— 选客户、勾服务，价格自动算出来。

> 价格表页面的结构是 **游戏（一张价格表）→ 大类 → 服务项**。
> 服务项表单里的「游戏」和「大类」两个下拉是联动的：
> 换了游戏，大类列表只留这个游戏的和通用的；选了一个属于某个游戏的大类，游戏会自动跟着切过去。
> 这样就不会出现「游戏选崩铁、大类却是原神的日常」这种自相矛盾的价格项。

### 五种计价方式

| 方式 | 用在什么上 | 例子 |
| --- | --- | --- |
| 固定价 | 一口价的服务 | 周本全清 25 元 |
| 按天 | 包月、日常托管 | 每日委托 5 元/天 × 30 天 |
| 按次 | 一次一次算 | 清体力 3 元/次 |
| 按数量 | 数量越大越便宜 | 深渊 1~5 层 30/层，6~12 层 25/层 |
| 套餐价 | 打包一堆内容 | 活动全包 120 元/套 |

## 三、七个模块分别管什么

### 游戏管理
游戏名、简称、图标、区服列表、**货币名称**、排序、上架/归档、备注、**顶部提示**。

**货币名称**填这个游戏里客户最认的那种货币（原石 / 星声 / 纠缠之缘…）。
填了之后，服务项表单里就会多出一栏「可获得货币（星声）」，写这个服务项能给客户拿到多少。
一个游戏一种货币；没填就不显示，服务项上那个数也不会有单位。

**顶部提示**是对外给客户看的一句话（可以多行，一行一件事），和「备注」分开：

- 备注是你自己记账用的，**不会出现在导出里**；
- 顶部提示会出现在**导出图片 / Word 文档的最上方**（抬头下面、第一个大类上面），
  所以写之前想一下「这句话客户看到会不会有问题」。

导出多个游戏合并成一份时，顶部提示不会硬提到最上面（免得「鸣潮的提示」被当成整张表的说明），
而是各自跟在对应游戏的小标题下面。价格表页面里也会在游戏表头下面显示一遍。

界面上**不写「公告」这两个字**：提示条就是暖色底 + 左边一道朱砂竖线，自己就说明白了。
大类也有同款，见下面「两级提示」。

**删除是归档，不是真删。** 老订单里冻着游戏名，真删了档案就断了。
真要彻底删除，列表里也有那个按钮，但会先告诉你有多少订单和凭证挂着它。

### 服务与价格管理

价格表页面按 **游戏（一张价格表）→ 大类 → 服务项** 三层展开。
整页是按「一张价目表」来排的，不是按「一堆列表项」来排 —— 三级靠**字体、栏线和留白**区分：

```
鸣潮  官服                                  9 个大类 · 73 个服务项   [+ 新建大类]
═══════════════════════════════════════════════════════════════════════════
▌地图全收集 1230（星声 4.5W）                    ← 游戏的顶部提示（通栏）
▎日常  [每天做]  期间都会免费帮领取…  ──────────── ¥70 – ¥300  4 项
  ▌包月客户这个大类里所有套餐都能换着做。          ← 大类的提示（缩进、字小一号）
    单次下单按套餐算，不拆开卖。
    日体套餐                                      ¥70 /30天
    含 每日活跃+每日体力
▎探索 100%  按数量逐步定价  ──────────────────── ¥40 – ¥70  4 项
    瑝珑声匣 ············································· ¥50 /单
```

- **游戏表头**最大（大字 + 账簿双线），往下滚的时候**吸附在顶栏下面**，
  看一眼就知道自己在哪个游戏里；
- **大类**是中号字 + 前面一道朱砂刻度，名字后面一条栏线拉到底，
  右边坐着**价格区间**和项数 —— 所以收起状态也能扫一遍价位；
- **服务项**是账目行：名字在左、金额在右（等宽数字，一列对齐），中间点线相连；
- **管理按钮平时是收起来的**（鼠标进到那一行才出现），所以正文永远是一张能直接读的价目表。

#### 服务项能拿多少游戏货币

游戏上填了**货币名称**之后，服务项表单里就多一栏「可获得货币（星声）」，填这个服务项能让客户拿到多少。

- 客户视角：导出图片 / Word 里，这一行紧跟在服务名下面、说明文字上面 ——
  `可得 星声 240`，比说明重一档，说明被截断也不会把它挤掉；
  价格表页面和详情抽屉里是一个小标签（`星声 240`）。
- 归类规则：数量记在服务项上，**名字跟着游戏走**（服务项自己没绑游戏就跟大类走）。
  游戏没填货币名、或者服务项没填数量，就什么都不显示 —— 不会出现一个没有单位的数字。
- 一个游戏一种货币。留空 = 不显示。

#### 两级提示：游戏的排最上面，大类的排在这个大类里

游戏和大类都能写一条**对外提示**，都不用「公告」这两个字：

| | 写在哪 | 出现在哪 |
| --- | --- | --- |
| 顶部提示 | 游戏表单 | 整份价目表的**最上方**（抬头下面、第一个大类上面），通栏 |
| 大类提示 | 大类表单 | 这个**大类的名字下面**、服务项上面，缩进一格、字小一号 |

两处都跟「备注」分开：备注是你自己看的，**一个都不会进导出**。
导出图片和 Word 用的是同一份模型，所以两边看到的排版和内容完全一致。

#### 大类也能归档 / 彻底删除

大类那一行鼠标放上去，操作组里最后一个是垃圾桶：

- **归档大类**：先从价格表里收起来，服务项、价格、阶梯价全部原地不动；
- **彻底删除**：大类没了，底下的服务项**不会跟着消失**，只会变成「未分类」，
  还能重新归到别的大类里。已经开出去的老订单也不受影响 —— 价格冻在下单那一刻。

两个都会先告诉你这个大类底下挂着多少个服务项，再让你选。

- **服务项必须挂在大类里**，所以新建服务项的入口只在大类行上，没有「直接建服务项」这条路。
- 每个服务项能改价、改说明、上架下架。
- 按数量计价的可以配**阶梯价**。
- **增项**可以挂在某个服务项下，也可以建成全局通用（比如「全程录屏」）。
- 没绑游戏的大类会归到「通用」组；早期没归到大类的服务项会落在「未分类」里，照样能改。

#### 没填备注和套餐内容的服务项，会自动压成一行

规则很简单，**只看这一个服务项自己填了什么**，跟它属于哪个大类无关：

- **没填备注、没填套餐内容、没挂增项、没有阶梯价** → 排成一行：
  `北落野 ························· ¥25/单`
  鼠标放上去才露出拖动把手和「详情 / 改」两个按钮（触屏上一直显示）。
- **填了上面任何一样** → 照常铺开成多行，把内容都显示出来。

所以像「8 个地区价」那种，填了备注的那几行是铺开的，只有名字和价格的那行是紧凑的，
不会再在行里留一片空白。

#### 大类和层级

**大类默认全部收起。** 一进价格表先看到的是「这张价格表里有哪些大类、各值多少钱」，
想看哪个再点开哪个，不用在一屏拉不到底的长列表里翻。谁点开过就记住谁（刷新页面也还在）。
往收起的大类里加服务项时会自动帮你展开，方便看刚加的那条。

收起状态下也**不是**只能看到名字：每个大类右边都有价格区间（`¥70 – ¥300`）和项数，
扫一眼就知道这个大类值不值得点开。工具栏上还有**「全部展开 / 全部收起」**一次到底。

为了让「大类」和「服务项」一眼分得清：

- 游戏是**表头**：最大号字 + 账簿双线，吸顶；
- 大类是**分组标题**：中号字、前面一道朱砂刻度，后面一条栏线拉到底；
- 服务项是**账目行**：名字左、金额右，中间点线，缩进对齐到大类名字。

#### 拖动排序

**服务项**和**大类**都能拖，两套互不干扰：

- **按住一个服务项拖** —— 调整它在当前大类里的位置；
  **拖到另一个大类里**，就等于同时把这个服务项换了归属（游戏也跟着大类走）。
- **按住大类的标题拖** —— 调整大类顺序；
  **拖到另一个游戏那一组里**，就等于把这个大类换了游戏。

拖动时会有一条朱砂色的插入线告诉你落在哪。

顺序存在 `sort_order` 上，拖完会把整份顺序写回数据库，
所以刷新、换设备看到的位置都一样。

排序基于完整数据而不是当前显示的内容，**所以开着搜索或筛选拖也不会漏掉没显示的项**。

> 拖动用的是浏览器原生的拖放，鼠标和触控板都好使；纯触屏（手机）上拖不了，
> 那种情况就在电脑上排一次，手机上照着看。

改价格表**只影响之后开的单**。已经开出去的老单冻在下单那一刻的价格上。

### 导出价格表（图片 / Word 文档）

价格表右上角有个「**导出图片/文档**」。点开是这样一个面板：

```
导出范围    [每个游戏各出一份（推荐 · 分开的文件） ▾]
每个大类最多列几项 [6 项 ▾]   最多列几个大类 [8 个 ▾]
带说明文字  ☑     联系方式 [微信：xxx]   页脚说明 [价格随版本更新…]

预览  ┌──────────────┐
      │  渲染好的图片  │      ← 改任何选项，预览实时重画
      └──────────────┘

[关闭]                    [生成 Word 文档]  [生成图片]
```

**默认按游戏拆开，一个游戏一份文件，不会把几个游戏混在一起。** 发给客户时只发他那款游戏那份。
如果确实想要一张总表，把「导出范围」改成「全部游戏合并成一份」就行。

- **图片**：PNG，1080px 宽、2 倍图（实际 2160px），直接发微信、发朋友圈都清楚。
- **文档**：真正的 `.docx`，Word / WPS 都能打开和二次编辑。用的是「服务名 ······ 价格」的点线排版。
- **两者内容完全一致**——都从服务端同一个导出模型生成，不是两套逻辑各画一遍。

导出会自动裁掉多余内容，目的是**一张图一眼能看完**，不是把整张价格表塞进去：

| 裁掉什么 | 怎么处理 |
| --- | --- |
| 已下架的大类 / 服务项 | 不导出 |
| 空的大类 | 不导出 |
| 每个大类超出条数的服务项 | 折成「…… 这个大类还有 N 项」 |
| 超出数量的大类 | 折成「…… 还有 N 个大类没有列出」 |
| 过长的说明 | 截断成一行 |

导出是**跟着数据结构走**的，以后你新加什么都会自动带上，不用改代码：

- 新游戏 → 自动多出一份，并带上游戏小标题
- 新大类 / 新服务项 → 自动进对应分组
- **阶梯价** → 转成提示，例如「1-5层，最多到 ¥25/层」
- **增项** → 写进说明，例如「增项：加急 +20%、指定角色 +15元」
- **套餐内容** → 写进说明，例如「含 每日活跃+每日体力+周本」
- **没归到大类的服务项** → 不会静默丢掉，会落到「未分类」里一起导出
- 起订量 > 1 的 → 标出「起订 N 天」

### 客户管理
昵称、**头像**、手机号、微信、QQ、来源、标签、备注。点进客户档案能看到他的全部订单、收款流水、
登录凭证、报价单，以及累计金额和欠款。

**头像**选填，传一张图（1.5MB 以内）就行 —— 会显示在客户列表、客户档案页和订单列表的客户格上。
客户多了、重名了、或者名字很像的时候，一眼就能对上人。没传头像的用昵称首字当占位。

客户反复下单也不会乱：

- 客户档案里**先列在做的、已结束的收在后面**，各自封顶，多的折成「还有 N 张…」。
- 订单列表的客户格标出这是他的**第几单**，回头客一眼看得出。
- 订单页可以**按客户排**（同一个客户的单聚在一起），也可以点客户名直接进档案。

### 登录凭证保险箱
单独一张表，和联系方式分开。见下面第四节的规矩。

### 订单管理
下单那一刻会把**快照**冻住：客户名、游戏名、服务名、单价、数量、总价、
套餐内容、增项、下单时间。之后你改价格表，这张单一个数字都不会变。

#### 挑服务（下单台和报价单里都有）

```
挑服务                                        勾上就进单
[搜服务名…]  [全部游戏 ▾]  [全部大类 ▾]

▎日常                                          4 项      ← 分类标题吸顶，滚到哪都知道在哪
┌──────────────────────────────────────────────────┐
│ ☑ 活跃套餐                              ¥25/30天  │      ← 勾上的行整条提亮，左边一道朱砂
│   固定价                                          │
│   [2] 30天   [改价] 元                            │
├──────────────────────────────────────────────────┤
│ ☐ 日体套餐                              ¥50/30天  │      ← 没勾也看得到价格
│   固定价 · 周本可指定                              │
└──────────────────────────────────────────────────┘
[2] 已选                                    清空
```

- **可以按大类筛**。搜索、游戏、大类三个条件是「都要满足」，一起用。
- **大类列表跟着游戏走**：选了游戏就只列这个游戏的大类（加上通用的）；
  选过的大类要是不属于新游戏了，会自动退掉，免得筛出个空列表。
- 分类标题**吸顶**，滚到哪儿都知道自己在哪个大类里，右边标着这个大类有几项。
- **价格常驻显示**，不勾选也知道多少钱。
- 底部固定一条「已选 N 项」，旁边有「清空」。
- **筛掉不影响已勾的**：勾好、填好数量之后再换筛选条件，勾选和数量都还在，
  合计也照常算着它们。
- **增项里标了「默认选中」的，勾上这个服务项就自动带上**，不用每次手动补勾
  （价格表里那个「默认选中」的勾才算数）。

#### 订单上也看得到「可得货币」

游戏上填了货币名、服务项上填了数量之后，**开单的全过程都能看到能拿多少**：

- **挑服务时**：服务名旁边一个小标记 `星声 13000`，挑的时候就摆在眼前；
- **金额汇总里**：多一行「可得 · 星声 15000」，勾几个就自动加（同一个货币才合计，
  跨游戏混了两种会分着写，不硬加）；
- **订单详情 · 服务明细**：每条下面一行 `可得 星声 26000`；
- **服务明细的面板底部**：`共 3 项 · 可得 星声 28000 · 合计 ¥700`。

数量和货币是**相乘**的：一条 `300/单 × 2` 的服务项，可得就是这个服务项的两倍。

**和价格一样冻在下单那一刻**：快照里存的是「每个的数量」，之后你在价格表上改了数字，
这张老单还是当时说好的那个数。老单（加这个功能之前开的）没有这段数据，就不显示这一行。

#### 交付日期会按「每天都做」的服务项自动算

单子里勾了**每天都做**的服务项时，**交付日期自动填成「下单日期 + 这个服务项的天数」**：

```
下单日期 [2026/09/23]        交付日期 [2026/10/23]      ← 自动填的
▌剩余 30 天   下单到交付 30 天   按「日体」30 天自动填的，可以直接改
```

- 天数怎么推：单位写成 **`30天`** 就算 30 天（你库里日体/精托/全托都是这种写法）；
  单位是 **`天`** 就按数量算；**按天计价**又没写单位的也按数量算；
  单位是「单 / 次 / 层 / 个 / 套」这种推不出来的，就**不自动填**，留给你自己填。
- 勾了好几条每天都做的，取**最长的那个**天数。
- 数量改了（比如 2 份 = 60 天），交付日期跟着挪。
- **你自己动过交付日期，就不再自动改**；把日期**清空**就等于交回给自动。
- 把那几条每天都做的都取消勾选，交付日期会跟着清掉。

不要这个自动？把服务项或它大类的「每天都做」摘掉就不算了。

#### 今日已完成（日体、包天这种天天要做的单）

日体、包天这类单**每天都要做**，做完就整单标「已完成」是不对的 —— 明天还得接着做。
所以订单详情页上有一个**「今日已完成」**：

- 点一下，这张单这个「今天」就**从「在做」列表里挪走**（看板的「进行中调度」也一起挪走），
  但状态还是「进行中」，钱和进度都没变。
- **过了凌晨 4 点它自己回到「在做」列表**（是 **4 点，不是 0 点**）——
  干到后半夜的人，凌晨 1 点做完的日体应该还算当天。不用做任何操作，也没有定时任务：
  标记时存的是**那个工作日的日期**，日期对不上就自动失效。
- 标错了、想今天就接着做 → 详情页按钮变成**「撤销今日完成」**，点一下回来。
- 想找这个「今天」标过哪些 → 订单页有个**「今日已完成」**筛选档。
- 已经真正「已完成」或「已取消」的单不给标（会提示）。

同一页上还有一个**「标记完成」**，那是**整张单结束**（永不再出现在「在做」里）。
状态机允许才会出现这个按钮 —— 还没确认 / 还没付款的单，得先走完前面的状态。

##### 哪些算「每天都要做」

**标在大类上**，不在单个服务项上：

- 名字里有**日常 / 日体 / 包天 / 每日 / 托管**的大类，建的时候**自动勾上**，
  以后新加的大类也认得出，不用手动设。
- 也可以在**大类表单**里手动勾 / 取消，价格表的大类标题上会显示「每天做」标记。

所以**以后往「日常」大类里加新的服务项，自动就算每天做** ——
哪怕那个大类和服务项是你明天才建的。

如果某个服务项要跟大类不一样（比如日常大类里的一次性附加项），
在**服务项表单**的「每天都做」里选「是 / 否」单独覆盖；默认是**跟随大类**。

##### 一张单里混着日常和一次性的活怎么办

比如「30天日体 + 两个活动」。两个办法，看你想要哪种：

**① 拆单**（订单详情右上角「拆单」）—— 把一次性的活挪到一张新单上，
两边**各自收款、各自结单**，互不牵扯：

```
DH260921-001  30天日体 + 两个活动     ¥130
        ↓ 拆单（勾上那两个活动）
DH260921-001  30天日体                ¥50     ← 天天标「今日已完成」
DH260922-002  30天日体（拆出）        ¥80     ← 自己走完成 / 收款
```

钱怎么分，规则是**说清楚**的：

- 每个服务项自己的金额（含它的增项）**跟着它走**；
- **折扣 / 手续费 / 成本留在原单**，新单从 0 开始（拆完可以各自再改）；
- **收款**在弹窗里选：
  - **按金额比例分到两张单**（默认）—— 已经收过的钱按两张单的新金额拆开，
    两边**各自结清**，加起来正好等于原来收的那笔（零头留在原单）；
  - **全部留在原单** —— 原单会变「多收」，拆的时候会提醒你多收了多少钱。
- **进度时间线**在弹窗里选：**留在原单**（默认）或**跟到新单**。
  进度是一段自由文字，没跟具体服务项挂钩，所以只能整批走或整批留。
- 客户、游戏、下单日期、交付日期、状态都照抄过去；标题会标「（拆出）」、备注写「拆自 DH…」。
- 原单必须**至少留一个**服务项，不能全拆走（整张都要挪的话，直接改那一张就行）。
- 拆出来的那笔收款也会标「拆自 DH…」，收款流水里能看出它是怎么来的。

> 收款和进度这两个选项只在**这张单已经记过收款 / 进度**时才出现，没记过就不问。

**② 不拆，直接标「今日已完成」** —— 点的时候会**先提醒你**，
把这张单里除了日常之外的活列出来（`若梦仍有回声、群声共振模拟域`），
让你确认这些也做完了。全是日常的单不会弹这个提醒，一步就标上。

订单详情的「服务明细」里，每天做的那条会带一个**「每天做」**标签，一眼看得出哪部分是日体。

#### 客户手机号

订单列表的客户格里直接显示**手机号**，要联系客户不用点进档案。客户头像、手机号、
「第 N 单」都在同一格，客户多了也能一眼对上人。

状态流转：

```
待确认 → 待付款 → 进行中 → 待验收 → 已完成
   ↘        ↘        ↘        ↘      ↓
              取消 / 售后 ←──────────┘
```

未按顺序跳转会被拦下来。**收款收满会自动从「待付款」推进到「进行中」**，省得再点一次。
已经记过收款的订单不允许直接删除（会让账对不上），要删得再加 `force`。

### 进度记录
每张单下面一条时间线：日期、完成内容、资源前后对比、截图/录屏链接、备注。
改了状态也会自动补一条进去。客户问「做到哪了」直接把那条发给他。

时间线按**一叠卡片**排（重做过一版）：

- 日期左边一列，写「**今天 / 昨天 / 3 天前**」，后面跟一个绝对日期（`10月2日`）——
  相对日期好扫，绝对日期是证据；
- 轨道上的圆点**按顺序点亮**：最新一条实心带光晕，更早的是空心 —— 一眼看出「现在做到这」；
- 「做之前 → 做之后」是并排的两个数，下面再给一排**本次消耗**的数字片
  （`星声 −160` 这种，消耗偏红、增长偏绿），不用自己心算；
- 截图做缩略图网格，点开大图；录屏/图床链接单独一排。

**「分享进度」按钮**（在进度时间线右上角）会把整条时间线整理成一份汇报，两种形式：

- **图片** —— 一张竖图，暖纸底 + 朱砂栏线，和价格表那张图同一套视觉，直接发微信。
  带单号、游戏、状态、已收 / 还差、每条进度的日期和资源变化（`160 → 40`）、备注。
- **文字** —— 同样内容的纯文本，点「复制文字」就能粘到微信里，想改两句就改。

截图原图塞不进这张图里，图上只会写「附 N 张截图」，图还是自己另发。

看板还会把**两天没记进度**的在做单挑出来提醒你。

#### 记进度时不用手抄资源数字

「记一条进度」里的**资源对比**两栏都有两个按钮：

- **自动识别** —— 点击后切回鸣潮窗口，按 **B** 打开背包识别贝币和星声，
  按 **ESC** 返回后再按 **M** 识别体力，最后再按 **ESC** 回到游戏。
  场景背景不需要和固定截图一致；程序以是否识别到贝币和星声来确认背包已打开。
  每个数字要**认到两次以上**才填进来。每页最多扫八帧，仍有缺项就按 ESC 返回并停止；
- **识别截图** —— 选一张游戏截图，这次**直接拖整张图进来就行**
  （以前要压到 1.5MB 以内，现在 12MB 以内都收）。

自动切回默认按鸣潮窗口标题和安装路径查找；如果你的游戏进程名称特殊，可在启动前设置
`XFC_GAME_PROCESS` 为进程名（不带 `.exe`），再重启本程序。

连着记的时候，「做之前」会自动带上一条的「做之后」，不用重抄一遍。

它认的是**图标**、不是坐标，所以换分辨率不会散架：1280×800 到 3840×2400 全都认对
（下面「七、屏幕识别」一节有实测表，也有超宽屏那个真实上限的说明）。

认不出来时**不会瞎填**：宁可留空。想让认得更全，可以在**设置 → 屏幕识别**里
装一个本地 OCR 引擎（下面「七、屏幕识别」一节有说）。

**收款类型**有四种：**定金 / 全款 / 尾款 / 退款**。
第一次收款默认选「全款」（一次付清最常见），已经收过一部分再记就默认「尾款」。

### 财务
按时间段看：订单额、总收款、退款、净收、应收余额、平台手续费、成本、利润。
还有每日开单柱状图、按支付方式分组、按游戏分组、未结清清单、收款流水。

口径：订单额按**下单日**归集，收款按**到账日**归集，两者不必同月。
利润 = 订单额 − 平台手续费 − 成本，不含你自己的人工。

### 报价单
勾服务 → 价格自动算 → 实时生成一张报价单，可以**一键复制成文字发微信**，
也可以存下来。客户点头后，报价单**可以直接转成订单**。

## 四、保险箱的规矩

这是整个后台最敏感的地方，规矩是硬的：

- **优先扫码登录。** 能不存密码就不存密码——登录方式选「扫码登录」时，
  这条凭证可以一个密码字段都不填。
- **密码绝不存明文。** 账号、密码、密保、备注整块用 **AES-256-GCM** 加密后写进数据库。
- **密钥不存在任何文件里。** 它由你的「保险箱密码」用 scrypt（N=32768）推导出来，
  只活在服务器内存中。服务器一重启、你手动落锁、或者闲置 20 分钟，密钥就没了。
- **查看和复制要过第二道门。** 保险箱没解锁时，列表里只显示脱敏提示（`wa*****@qq.com`），
  内容是一张「封」条。要看明文得先输独立的保险箱密码。
- **谁、什么时候、看了哪条，全部留痕。** 「取用记录」里连解锁失败都记。
- **不存短信验证码、不存临时密码。** 那些一次性用完就该消失。
- **改保险箱密码会重新加密所有凭证。** 改之前建议先导出一份备份。

> ⚠️ **忘了保险箱密码就真的解不开**，没有后门、没有找回。请记在密码管理器里。

### 关于局域网访问的安全边界

用手机通过局域网访问时走的是普通 HTTP，**同一个 WiFi 下的其他人理论上能抓包看到你输入的密码**。
所以：

- 只在自家或信得过的 WiFi 下用手机访问；
- 在陌生网络里就用 `DaiganLauncher.exe --local` 只开本机；
- 后台对登录和保险箱解锁都做了失败限速（10 分钟内错 8 次就锁一段时间）。

## 五、备份与搬家

**数据全在 `data/` 目录里。** 把整个文件夹拷走就是完整备份。

也可以走「设置 → 导出一份备份」，会下载一个 JSON 文件（含全部业务数据）。
凭证在文件里仍然是**密文**，换台电脑要用同一个保险箱密码才能解开。
「从备份恢复」会用备份内容**覆盖**现在的全部数据，所以操作前会要你确认。

> SQLite 的 `data/console.db` 是主库，同目录下的 `-wal` / `-shm` 是它的运行时文件，
> 手动拷贝时三个一起拷最稳妥；用「导出备份」则没有这个顾虑。

```bash
npm run test:ui                   # 界面冒烟：真浏览器点一遍主要页面和抽屉（见下）

node scripts/vision-parity.mjs    # 屏幕识别后端对照：旧引擎链 vs Python 后端，逐档比结果和耗时

```

`inspect.mjs` 和 `reset-password.mjs` 都支持 `--data <目录>` 指向别的数据目录，
比如 `node scripts/inspect.mjs data/console.db`。

这两个脚本都**只动登录密码那两行设置**，游戏、价格表、客户、订单、凭证一概不碰。
保险箱密码是另一套，不受影响。

### 调界面时怎么截图

零依赖，用的是系统里现成的 Edge + Node 自带的 WebSocket（不需要装 puppeteer）：

```bash
node scripts/shot.mjs --url http://127.0.0.1:8802 --password 临时密码 \
     --route /price --out shots/price.png --width 1280 --height 900
```

它自己会登录、等页面渲染好、再截图，常用参数：

| 参数 | 作用 |
| --- | --- |
| `--route /price` | 登录后停在哪个页面 |
| `--full` | 截整页（默认只截一屏） |
| `--clip x,y,w,h` | 只截某一块，配合 `--scale 2` 看细节 |
| `--scale 0.5` | 输出缩放，缩小省事、放大看字 |
| `--wait ".pricelist"` | 等这个选择器出现再截 |
| `--scroll 1500` | 先滚到某处（验吸顶这种效果） |
| `--theme dark` | 切深色帐面 |
| `--eval-file x.js` | 截图前在页面里跑一段 JS（展开大类、点开抽屉…） |

**别用 `--eval` 传复杂 JS**：PowerShell 会把带分号/花括号的参数截断，
脚本一律写文件用 `--eval-file`。另外**不要**用 `--virtual-time-budget`，
这个 Edge 版本下虚拟时间会在请求落地前烧完，截出来永远是空壳。

### 接口冒烟测试

```bash
npm run test     # 242 项，从初始化跑到财务结算，一条命令
```

它**自己起一个干净实例**（数据目录 `data-smoke-run`，端口由系统分配，不跟 8787 抢），
跑完关服务、关库；全绿就把数据目录删掉，有失败就留着，方便进目录里翻库和上传件。
**不碰 `data/` 里的真数据。**

```bash
# Windows
set XFC_DATA_DIR=./data-smoke && node server.mjs --port 8790 --local

XFC_DATA_DIR=./data-smoke node server.mjs --port 8790 --local
```

然后另开一个终端 `node scripts/smoke.mjs`（实例地址用 `XFC_BASE` 覆盖，默认 `http://127.0.0.1:8790`）。
`npm run test` 还有两个开关：`XFC_SMOKE_KEEP=1` 跑完保留数据目录，`XFC_SMOKE_DATA_DIR=<目录>` 换一个目录
（那个目录会被整个删掉重建，所以只接受 `data-smoke*` 这种名字，或者系统临时目录里的路径）。

### 界面冒烟测试

```bash
npm run test:ui               # 约 1 分钟：起实例 → 种一份最小数据 → 真浏览器点一遍
npm run test:ui -- --shots    # 顺手把每个页面截一张图存到 shots/ui-smoke/
```

接口那 242 项断言看不见界面这一层：页面要开抽屉、要开弹窗、要拿浏览器的
`<dialog>` / canvas / 剪贴板，这类东西**只有真点下去才会炸**，构建也看不出来。
所以这里用无头 Edge 走一遍：

- 登录页 → 登录 → 工作台外壳；
- 总览 / 订单 / 客户 / 价格表 / 游戏 / 财务 / 报价单 / 保险箱 / 设置 / 自媒体，
  以及客户档案详情：每页都要渲染出内容、内容里有该有的字、**页面零报错**；
- 关键交互：价格表「看服务详情」、报价单顶部「做报价单」、开单台挑服务算钱、
  订单详情的记进度/记收款/推进状态/分享进度/删单、保险箱的登记/解锁/看明文/审计/删除、
  设置页的改店铺信息/改密码/导出备份/清空确认、客户档案的改资料/归档三选一 ——
  点下去必须开出抽屉或弹窗，且里面有该有的内容，该落库的落库。
- 会真动手的两处：客户档案的**真归档**（名下有订单的那位，归档后状态变 `archived`、
  订单不连坐，最后还原回 `active`）和**真删除**（另建一个一次性客户，硬删完接口 404）；
  设置页会拿一个错密码去提交，看服务端报错有没有显示在抽屉里（真密码不动）。
- 对账：财务页八个格子（订单额 / 总收款 / 退款 / 净收 / 应收余额 / 手续费 / 成本 / 利润）
  必须和同一区间 `/api/finance/summary` 的数字逐个相等，收款流水的笔数要对上
  `/api/payments`，换区间（本月 / 今年 / 自定义）数字要跟着重算 —— 界面算错钱比崩了更难发现。

机器上没装 Edge/Chrome 时会明确打印「跳过」并以 0 退出（不假装测过）；
想指定浏览器用 `XFC_UI_BROWSER=<路径>`，换 CDP 端口用 `XFC_UI_CDP_PORT`。
它的数据目录规则和 `npm run test` 一样：全绿删掉，有失败留着。

> 它不在 `npm run check` 里：一分钟对提交前太慢，而且依赖机器上装了浏览器。
> 想连它一起过就用 `npm run check:full`。

### 提交前的闸门

`hooks/pre-commit` 会在提交前跑「语法自检 + 接口冒烟」，一条 `git config core.hooksPath hooks` 启用；
急的时候 `git commit --no-verify` 跳过。它故意**不跑构建、也不跑界面冒烟**（慢），
想全量过一遍就用 `npm run check:full`。

> `public/dist/` 不进版本库（构建产物），但界面冒烟跑的是磁盘上那一份，
> 所以改完前端记得 `npm run build` 再 `npm run test:ui`，别拿旧产物测新代码。

## 七、屏幕识别（记进度时自动读资源数字）

这一块的目标只有一句话：**别手抄游戏里的星声/体力/贝币**，而且
**换分辨率也得认得出、数得准**。

### 它是怎么认的

不看坐标，看**图标**。顶栏那几个资源图标是同一份美术资源，程序拿模板去对：

1. 先在画面上方那条带里找**最好认的那个图标**（星声，内部对比强）当**锚点**；
   锚点的像素尺寸就是这一屏的缩放系数 —— 所以 1280 和 4K 用的是同一套逻辑，
   没有「y≈54 那一行」这种写死的坐标；
2. 其余图标（贝币、体力）只在锚点附近这一簇里找，**离锚点太远的候选一概不认**
   （实测界面左边有个亮块会被误认为贝币，然后读到隔壁星声的数字）；
3. 数字由 OCR 读，但**按几何关系把碎片拼回一个数**：
   OCR 会把 `2174` 切成 `21` + `74`、把 `129/2000` 切成四块，
   按「同一行 + 缝隙小」拼回去，再取图标右边最近的那一块；
4. **每个数字要认到两次以上（跨帧投票）才填进表单**。两次不一致就接着看，
   到时间还没凑够就留空 —— 认不准的时候它绝不硬凑一个数字。

截屏这一步还有一条不显眼但致命的规矩：**截到的必须是游戏画面，而且跟 Windows 的
显示缩放无关**。点击自动识别后会先激活鸣潮窗口，按上述顺序切换背包和地图，
并按游戏窗口边界截取；
`scripts/grab.ps1` 会先把自己标成 DPI 感知，再读取窗口位置 ——
少了这一步，在 150% 缩放的 2560×1600 屏上它以为屏幕只有 1707×1067，
`CopyFromScreen` 就只抓了**左上角那一块**（不是整屏缩小）；而上面那个锚点在画面
宽度 ~89% 处，正好整个落在被裁掉的部分里，于是一个数字都认不出来。
`vision-selftest` 里有一条**截屏自检**专门守这件事：拿 `scripts/screen-info.ps1`
问来的真实显示模式（`EnumDisplaySettings`，不受 DPI 虚拟化影响）跟截出来的图比，
对不上就直接判失败。

实测（同一台机器、同一张截图缩到不同尺寸）：

| 分辨率 | 认出来的星声 | 认出来的贝币 |
| --- | --- | --- |
| 1152×720 | 2174 ✓ | 2508319 ✓ |
| 1280×800 | 2174 ✓ | 2508319 ✓ |
| 1366×854 | 2174 ✓ | 2508319 ✓ |
| 1600×1000 | 2174 ✓ | 2508319 ✓ |
| 1920×1200 | 2174 ✓ | 2508319 ✓ |
| 2559×1599 | 2174 ✓ | 2508319 ✓ |
| 3413×2133 | 2174 ✓ | 2508319 ✓ |
| 3840×2400 | 2174 ✓ | 2508319 ✓ |

**话说清楚，超宽屏有个真实的上限**：2560×1080、1920×822、3440×1440 这类比例下，
游戏 UI 是按画面高度缩的，顶栏那排字只有 14~22px 高 ——
**Windows 自带的 OCR 在这个尺寸上会读错位数**（`2174` 读成 `21`，放大到 3 倍也一样，
因为原图信息量就那么多）。这时候程序会**明确标出「字太小，务必核对」**，
让你对着游戏看一眼，而不是悄悄填个错的进去。
想在这种分辨率下也认准，就得装下面说的本地 OCR 引擎（PP-OCR 系对这种小字强得多）。

耗时（2560×1600 那台机器实测，两个后端都量过）：

| | 冷（第一次点，要整条带找锚点定标） | 热（同一分辨率再认一帧） |
| --- | --- | --- |
| 装 RapidOCR-json | ~2.7s | ~0.9s |
| 用 Python 视觉后端 | ~3.0s | ~1.1s |

这一帧里**大头是图标匹配（冷 2.8s / 热 0.4s），OCR 只占 ~0.6s** ——
所以想再快，方向不是换 OCR，而是别每帧都重新找图标（跨帧记住标定 + 只认那几个数字块）。

> 改动识别相关代码（`src/vision.mjs` / `src/screen.mjs` / `src/ocr.mjs` /
> `integrations/screen-vision/` / `scripts/grab.ps1`）之后，跑一下
> `node scripts/vision-selftest.mjs` ——
> 它先真截一次屏核对「截到的是不是整屏」（显示缩放变了、截屏脚本退回 DPI 不感知，
> 都会在这里当场报出来），再拿 `shots/samples/` 里的真截图把这十一种分辨率过一遍，
> 能立刻看出哪一档退化了。要比较两个后端就再加一步 `node scripts/vision-parity.mjs`。
> 没有样例图它会自己跳过，不会让 `node scripts/check.mjs` 失败。

### 想认得更全，装一个本地 OCR 引擎（推荐，能一键装）

不装也能用（走 Windows 自带的 OCR），但**装了差距很大**：同一批截图，
自带 OCR 在超宽分辨率下会把 `2174` 读成 `21`，换上 PP-OCR 系的引擎之后
**十一种分辨率全对**（22/22，含 2560×1080 / 1920×822 / 3440×1440 这些超宽比例）。

**怎么装：设置 → 屏幕识别 → 「Python 视觉后端」→ 点「一键安装依赖」。**
它会建一个项目内的 `data/vision-venv`（不动你系统里的 Python），装 RapidOCR + ONNX Runtime，
约 200MB，装完程序重启会自己起（也可以当场点「启动」）。模型**复用**仓库里已有的
`tools/ocr/rapidocr/models/`，不额外下载。界面上有进度、步骤和日志，
点「自检一下」是**真认一张图 + 真认一个数字块**，装错版本、缺 DLL 都会当场现原形。

装完回到 **设置 → 屏幕识别 → 重新检测**，它会告诉你现在用的是哪个。
六个引擎全都没有才会告诉你「用不了」，不会因为缺一个就罢工。

| 顺序 | 引擎 | 能不能一键装 | 说明 |
| --- | --- | --- | --- |
| 1 | **Python 视觉后端** | ✅ 能（推荐） | RapidOCR + ONNX Runtime，跑在项目内 `data/vision-venv` 里，长驻进程（127.0.0.1:5410）。有置信度，还能只认一个小数字块（13ms）。见 `integrations/screen-vision/README.md` |
| 2 | **Umi-OCR** | ✋ 要手动 | <https://github.com/hiroi-sora/Umi-OCR> 官方包是自解压 exe，装完还要在它自己的设置里打开「HTTP 服务」（默认端口 1224）—— 最后一步得你点，所以这里只给下载页 |
| 3 | **PaddleOCR-json** | ✅ 能 | 约 88MB 包 / 展开 250MB，**要 CPU 支持 AVX**（老机器可能跑不起来） |
| 4 | **RapidOCR-json** | ✅ 能 | 约 70MB 包 / 展开 95MB，**不需要 AVX** —— 不用 Python 的话，装这个最省事 |
| 5 | **Tesseract** | 自己装 | <https://github.com/UB-Mannheim/tesseract> 安装时勾上 `chi_sim` 中文语言包 |
| 6 | **Windows 自带 OCR** | 不用装 | 兜底，永远在 |

自动安装需要这台机器上有**能解 .7z 的解压器**（7-Zip / NanaZip 之类）。
设置页会先探测并告诉你有没有；没有的话它会说清楚，并给出下载页让你手动解压到
`tools\ocr\`。想装到别处也行 —— 每个引擎都支持用环境变量指路径
（`RAPIDOCR_JSON_BIN` / `PADDLEOCR_JSON_BIN` / `TESSERACT_BIN`）。

> 引擎都是**本机跑**的，截图不出这台电脑，和凭证保险箱一个立场。
> 装到 `tools/` 里的东西不进版本库（.gitignore 里排除了），换机器重新点一次就行。

#### 换后端这件事有对照脚本，别凭感觉

```bash
node scripts/vision-parity.mjs          # 旧引擎链 vs Python 后端，11 档并排列出来
node scripts/vision-parity.mjs --quick  # 只跑两档，看个大概
```

它把两个后端各跑一遍同一份自检，逐档比结果和耗时，**有哪一档退化了当场就能看见**。
实测（2560×1600 那台机器）：两个后端都是 **22/22**，数字完全一致；
Python 那边每帧慢 ~200ms（热态整帧 1100ms vs 898ms），但多了置信度和那条 13ms 的
数字块识别 —— 后者才是把这一帧从 600ms 压下去的关键（下一步的事）。

> 引擎的「认字」这一层是可插拔的：`src/ocr.mjs` 里那个 `ocrImage()` 就是接缝。
> 强制用某一个引擎跑自检（排查问题时很有用）：
> `set XFC_OCR_ENGINE=python && node scripts/vision-selftest.mjs`，
> 或者 `node scripts/vision-selftest.mjs --backend=python`。

视觉后端这几个旋钮在需要时才用（默认值都能跑）：

| 环境变量 | 默认 | 什么时候用 |
| --- | --- | --- |
| `XFC_VISION_PYTHON` | 空 | 不想用项目内的 venv，指一个自己的 Python 解释器 |
| `XFC_VISION_PORT` | `5410` | 端口撞了（比如上次强杀留下的进程占着） |
| `XFC_VISION_AUTOSTART` | `1` | 设 `0` 就不自动起，只在设置页手动点「启动」 |
| `XFC_VISION_URL` | 空 | 后端跑在别处（另一台机器/容器），填 `http://host:port`，Node 就不再自己起进程 |
| `XFC_VISION_TOKEN` | 每次随机 | 配合上面那个：外部后端的令牌 |
| `XFC_VISION_MODELS` | 空 | 模型放别处时指路径 |
| `XFC_OCR_ENGINE` | 空 | 强制只用某一个引擎（自检/排查用） |

#### 临时文件为什么不放系统临时目录

**因为 `%TEMP%` 不一定写得进去。** 这是踩过的真实故障：程序在一个受限环境里跑时，
往 `%TEMP%` 写一个 2×2 的 PNG 直接被拒（`EPERM`），「自检一下」整个接口 500 ——
而原因跟识别本身毫无关系。

所以临时文件的落点统一走 `src/util.mjs` 的 `scratchFile()`，**两档偏好、三档兜底**：

| 偏好 | ① 先放 | ② 写不进就退 | ③ 还不行才退 | 谁在用 |
| --- | --- | --- | --- | --- |
| `project`（默认） | `data/tmp` | 系统临时目录 | —— | 只被我们自己读的（Python 侧解图走 `np.fromfile`，中文路径没问题） |
| `ascii` | 系统临时目录（纯 ASCII） | **项目旁边的纯 ASCII 联接** `..\xfc-tmp` | `data/tmp` | **要给外部 exe 读写**的 |

#### 那个 `xfc-tmp` 联接是什么

外部 exe 读不了中文路径（实测同一个 exe、同一张图：ASCII 路径 `code:100` 正常，
项目路径 `code:300 JSON dump failed`），而项目目录本身就叫「代肝价格查询」，
Windows 的 8.3 短名也**不帮忙**（实测本项目短名是 `D:\GITHUB~1\代肝价~1`，中文原样保留）。
唯一的出路是让**路径前缀**变英文：程序会在项目**外面**建一个英文名的目录联接
（junction）指回 `data/tmp`，于是 `D:\github_xm\xfc-tmp\xxx.png` 就是纯 ASCII 的。

- 放在项目外面：只有前缀算数；放同一个盘：联接不能跨卷；
- 用 junction 而不是 symlink：junction 是 Windows 上唯一**普通用户就能建**的类型；
- **懒建**：只在系统临时目录真的写不进去时才建，正常情况下你看不到它；
- 建不出来（父目录也带中文 / 盘不支持 / 没权限）就退到 `data/tmp` ——
  那时只有 Python 后端能用。

实测：把 `TEMP` 指到一个不存在的盘，**旧引擎链（RapidOCR-json 那个 exe）照样 22/22**，
和正常环境一致 —— 这条路在加联接之前是走不通的。

同一个根因还会咬到**所有现场编译 C# 的 PowerShell 脚本**，而且多数是**静默**的
（`Add-Type -TypeDefinition` 要临时目录，`Add-Type -AssemblyName` 不要）：

| 脚本 | 临时目录不可写时会发生什么 |
| --- | --- |
| `grab.ps1` | DPI 那步被 catch 成 `dpi=failed` → **静默截出缩放错的图**（2560×1600 截成 1707×1067）→ 之后所有识别全错 |
| `focus-game.ps1` | 直接**死在编译那一步**，游戏窗口没被激活 → 截到的是别的窗口 |
| `game-key.ps1` | 同样死在编译那一步，**按键发不出去** |
| `screen-info.ps1` | 什么都不输出 → 自检里「截屏是不是被 DPI 虚拟化了」那道**防线静默失效** |

所以这四个脚本统一 `dot-source` 一份 `scripts/lib/ensure-tmp.ps1`，开头先验一次临时目录
能不能写（真写一个文件再删），不行就退到项目自己的 `data/tmp`
（`grab.ps1` 退到「这张图本来要落盘的目录」）。**新增会编译 C# 的脚本，记得也接上这一句。**

修完的实测：把 `TEMP` 指到一个不存在的盘，这四个脚本的输出与正常环境**逐字一致** ——
`focus-game.ps1` 照样找到并激活 `鸣潮`、`game-key.ps1` 照样走到焦点判断、
`screen-info.ps1` 照样报 `2560 x 1600`、`grab.ps1` 照样 `dpi=per-monitor-v2`；
自检报「截到 2560x1600，物理屏 2560x1600 —— 整屏，DPI 感知正常」，十一种分辨率 22/22。

**注意 `scripts/*.ps1` 全部保持纯 ASCII、不带 BOM** —— Windows PowerShell 5.1 会把
无 BOM 的 .ps1 按 GBK 读，写中文注释会直接把脚本解析坏（`grab.ps1` 就这么坏过一次，
报的是 `Unexpected token '}'`）。这一条对所有 .ps1 都适用。

### 图标变了怎么办（换了游戏版本）

游戏大版本更新、把顶栏图标重画了，认不出来是正常的。设置 →
屏幕识别 → **自备一个图标模板**：给它一张顶栏截图 + 图标本体所在的方框
（x / y / 宽 / 高），程序当场把那个图标抠出来存进 `data/resource-icons/`，
以后优先用你这份（不动程序自带的）。

### 技术上的取舍（几句话）

算法在 `src/vision.mjs`：**积分图版 NCC 模板匹配**（OpenCV `matchTemplate` 的
`TM_CCOEFF_NORMED` 口径 + scikit-image 的工程形式）配上**由粗到细的多尺度搜索**，
外加**锚点定标 + 相对布局**（思路来自 Airtest 的 `record_pos` / `resolution`）。
一个第三方库都没引 —— 这是照着思路自己写的实现，不是搬代码。

之所以非要换掉老实现：老的每匹配一个位置都要重算窗口均值方差，
2559 宽的顶栏上光一次匹配就要 **21 秒**；现在同场景几十毫秒。
评估和踩坑记录都写在 `PORT-CANDIDATES.md` 里。

## 八、常见问题

**Windows 怎么启动、停止或重启？**
双击 `DaiganLauncher.exe`，在控制台里使用对应按钮；也可以直接带参数启动。
启动器会自动寻找 Node.js，并把日志写入 `launcher-data/server.log`。

**窗口一闪就没了 / 提示需要 Node.js？**
说明这台电脑上没找到 Node.js。去 <https://nodejs.org> 下载 LTS 版本装上。
如果刚装完还是提示找不到，**关掉窗口重新开一个新的**——PATH 的改动只对新开的窗口生效。

**点「生成图片」没反应 / 下载文件夹里没东西？**
浏览器可能把「连续下载多个文件」拦掉了。导出范围改成「全部游戏合并成一份」就只下一个文件；
或者允许这个网站「下载多个文件」再试。图片也可以用 Chrome / Edge / Safari 打开后台来生成。

**生成 Word 文档打不开？**
它是标准的 `.docx`，Word 和 WPS 都能开。如果被手机当成未知文件，先存下来再用 WPS 打开。

**提示端口被占用？**
换一个端口：`DaiganLauncher.exe --port 8888`。

**手机打不开那个局域网网址？**
确认手机和电脑连的是同一个 WiFi；Windows 防火墙第一次会弹窗，要选「允许访问」；
公司/学校网络常常禁止设备之间互访，那种网络下手机连不上是正常的。

**屏幕识别认不出来 / 认错了？**
按这几步看：

1. **先去 设置 → 屏幕识别 看它用的是哪个引擎。** 只有「Windows 自带 OCR」的话，
   在「Python 视觉后端」里点 **「一键安装依赖」**（约 200MB，需要这台机器上有 Python 3）——
   实测装完之后十一种分辨率全对，而自带 OCR 在超宽分辨率下会把 `2174` 读成 `21`。
   不想装 Python 也行：在「安装选项」里装 **RapidOCR-json**（约 70MB，不需要 AVX），
   结果一样（两个后端对照过，都是 22/22）。
2. **看提示里有没有「字太小，务必核对」。** 有这句说明当前是自带 OCR 且顶栏文字
   不到 26px 高（超宽分辨率下常见），对着游戏核一遍；装了上面那个引擎就不会再提示。
3. **换了游戏大版本、图标重画了？** 设置 → 屏幕识别 → 自备一个图标模板，
   给一张顶栏截图 + 图标所在的方框（x/y/宽/高），它会当场抠出来存下。
4. **一个数字都认不出来（连「没配上数字的」都没有）？** 那是截屏这一层的问题，
   不是识别的阈值问题：跑 `node scripts/vision-selftest.mjs`，第一条「截屏自检」
   会直接告诉你截到的是不是整屏（显示器缩放不是 100% 时最容易踩这个）。
5. **「Python 视觉后端」那张卡说「起来了但没就绪」/「依赖没装」？** 点「看日志」，
   它自己的 stderr 就在里面（载模型失败、缺 DLL、模型没找齐都会写在那儿）。
   点「自检一下」会真认一张图 —— 通过就说明能用，不用管状态字。
6. **说「5410 端口上已经有一个视觉进程，但 token 对不上」？** 那是上次程序被强杀时
   留下的 python.exe 还占着端口。正常情况下它会跟着主程序一起退（主程序一死，
   管道断开它就自己退出）；真留下了就在任务管理器里结束那个 python.exe。

想自己确认「换分辨率还认不认得出」，跑 `node scripts/vision-selftest.mjs`；
想比较两个后端，跑 `node scripts/vision-parity.mjs`。

**忘了登录密码？**
关掉启动窗口，然后：

```bash
node scripts/reset-password.mjs            # 清掉密码，下次启动回到初始化引导
node scripts/reset-password.mjs 新密码      # 或者直接设一个新密码
```

只会动登录密码，**游戏、价格表、客户、订单、订单凭证一概不碰**。
保险箱密码是另一套，不受影响（所以更要记住保险箱密码——那个没有后门）。

**价格表里为什么不能直接建服务项？**
因为结构是「游戏（一张价格表）→ 大类 → 服务项」。先在大类行上点「加服务项」，或者先「新建大类」。没绑游戏的大类会归到「通用」组里。

**换了台电脑，凭证打不开？**
备份文件里的凭证是密文，必须用**同一套保险箱密码**才能解开。
换了密码就不行了。

**想只在自己电脑上用？** 用 `DaiganLauncher.exe --local` / `./start.sh --local`。

## 九、技术上的事

- **本地优先**：后端保持 `node:http` + `node:sqlite` + `node:crypto`，前端构建依赖锁在 `package-lock.json`。
- 前端入口是 React 19 + Vite 8，页面和表单已经全部收敛到 React，统一使用 Lucide React 图标。
- 界面从「React 壳 + 旧命令式视图」搬到单栈的过程和现状，见下面「界面是怎么从旧栈搬到 React 的」。
- 密码用 scrypt 哈希；会话是 HttpOnly + SameSite=Lax 的 Cookie，有效期 14 天。
- 数据库开了 WAL 和外键约束；迁移按 `PRAGMA user_version` 顺序前进，只增不改。
- **钱的算法只有一份**：阶梯价规则在 `shared/pricing.js`，服务端（`src/pricing.mjs`）、
  React 组合报价弹窗和旧价格表页面（现在只当测试参照物）都调它。以前服务端和前端各有一份
  实现，一旦漂移就会「客户看到的价」和「实际收的价」对不上，而且很难发现。
- 订单口径（阶梯单价、日体、可得、进度、收款）同理，只有一份：`shared/order-calc.js`。
- 附 `PRODUCT.md` 和 `DESIGN.md`：前者是产品定义，后者是视觉与交互的规则书。

### 界面是怎么从旧栈搬到 React 的

壳层（导航、主题、路由、顶栏、侧边栏）是 React，八个业务页一页页搬完了，
**每搬一页就连那一页的表单、抽屉一起搬**，否则还是半吊子。顺序是按依赖从叶子往根：

```
游戏 → 客户 → 价格表 → 订单 → 财务 → 报价单 → 保险箱 → 设置 → 客户档案详情
```

**现在全部搬完了**，一页不剩。挑几件值得单独说的：

- **游戏表单**（`client/game-form.jsx`）—— 第一个全 React 的表单；
- **客户表单**（`client/customer-form.jsx`）—— 字段和提示跟旧的一字不差；
- **确认框**（`client/app/confirm.jsx`）—— 各页原先弹的都是旧 DOM 对话框，
  现在换成 React 渲染的，调用方式（`if (!await confirmDelete({...})) return`）一字未改；
- **价格表整页**（`client/price.jsx` + 五个浮层模块）—— 大类表单、组合报价、
  服务项表单、阶梯价编辑器、套餐增项编辑器、服务项详情抽屉、导出器，全部换成 React；
- **提示条**（`client/app/toast-store.js` + `client/app/toast.jsx`）—— 全站唯一一份
  toast 实现：谁都能 `toast()`，由 `<ToastHost />` 统一画，样式和时长不会再各走各的；
- **订单整页**（`client/order-composer.jsx` + `client/order-detail.jsx`）—— 开单台
  （挑服务、算钱、自动到期日、改明细）和订单详情（记进度、记收款、推进状态、
  分享进度、拆单、删单）都换成 React，`/orders`、`/orders/new`、`/orders/:id`
  三条路由全走 React；
- **报价单**（`client/quote-composer.jsx`）—— 做报价单/改报价单的抽屉，以及
  列表里那个「看文字版」弹窗（以前是旧 `modal`），一起换成 React；
- **保险箱**（`client/vault.jsx` + `client/vault-gate.jsx`）—— 凭证列表、登记/改
  凭证表单、明文取用弹窗、审计抽屉、解锁门禁（`promptUnlock` /
  `ensureVaultReady`）全部 React。门禁的**状态**仍然只有一份：
  `public/js/vaultgate.js` 里的 `vaultState` + `syncVault` + 监听器，设置页和
  保险箱页看到的是同一个真相；
- **设置整页**（`client/settings.jsx`）—— 店铺信息、改登录密码、改保险箱密码、
  屏幕识别（引擎列表 + Python 视觉后端那张卡 + 自动安装 + 进度轮询）、自备图标模板、
  导出/导入备份、清空数据，连同四个抽屉表单一起搬；
- **客户档案详情**（`client/customer-detail.jsx`）—— 客户名下的订单（在做/已结束
  各自封顶 + 「还有 N 张」）、收款流水、联系方式、账目、凭证脱敏列表，以及
  「归档 / 彻底删除」那个三选一（旧 `choiceDialog` 的 React 版）。

价格表这一页值得单独说一句：它的浮层是**互相叠**的 —— 服务项详情抽屉上点「阶梯价」
会再开一层，阶梯价里点「加一档」再开一层，删服务项时确认框又叠在抽屉上。
所以 `client/app/overlay-host.jsx` 从「一次只开一个」改成了**一叠**（每层各自一个
原生 `<dialog>`，浏览器管 top layer，Esc 只关最上面那层），滚动锁也交给宿主统一管
（里层关掉不能把外层的锁也解了）。防连点靠 key：同一把 key 已经在最上面就先关掉再开。

**旧栈已经清零**：`public/js/views/` 那一整批命令式视图（`price.js` / `orders.js` /
`orderbits.js` / `settings.js` …约 6000 行）、`client/lib/legacy-features.js`、
`client/lib/legacy-ui.js`、`public/js/ui.js`、`public/js/dom.js` 全删了。
`main.jsx` 里不再有 `view:` 适配器、`setActions` 管线和 `vaultgate` 传参；
认不出来的地址走 `client/app/not-found.jsx`（以前会偷偷退回总览）。
`public/js/` 现在只剩三个真正被 React 调用的文件：`pricecard.js`（画价格表图片）、
`progresscard.js`（画进度卡）、`vaultgate.js`（保险箱状态，只剩状态没有界面 ——
弹窗都在 `client/vault-gate.jsx`）。
`public/dist/` 也从版本库里拿出来了（`.gitignore` 里有一条）：`npm start` 的
`prestart` 会自动 build，不必再把 1.2MB 的产物提交进 git。

新表单照着这四块写：

- `client/app/overlay-host.jsx` —— 让 React 浮层能被命令式打开：
  `const saved = await openGameForm()`，取消得到 `null`，调用方式和旧的
  `formDrawer` 完全一样，所以页面代码几乎不用改；
- `client/app/drawer.jsx` / `client/app/modal.jsx` —— 抽屉和对话框本体。
  刻意沿用旧类名（`dialog.drawer` / `.drawer__head` / `.drawer__foot` /
  `dialog.modal` / `.modal__foot`），因为 `client/styles.css` 直接 `@import` 了
  `public/css/app.css`，样式能继承，迁移期间新旧浮层长得一模一样，不会出现视觉断层；
- `client/app/fields.jsx` —— 受控字段：文本、多行、下拉、逗号分隔（区服/标签）、
  勾选框、图片上传。同样沿用 `.field` / `.lbl` / `.inp` / `.ta` / `.sel` / `.err`；
- `client/app/confirm.jsx` —— 确认框（`confirmDialog` / `confirmDelete`）；
- `client/app/copy-button.jsx` —— 「复制价款」这类复制按钮。

**怎么确认「搬完长得一样」**：搬一页的时候，`npm run test:ui` 会把新旧两个表单在同一个
浏览器里各开一次，量出抽屉宽度、字段顺序、半宽/整宽、控件类型、每个字段的宽度、页脚按钮，
逐项对比（差 1px 以上就算不一致）。这比截图目测可靠 —— 结构和类名悄悄变了会当场红。

这一步真抓到过东西：旧引擎对自定义字段会补一个 `field--full`（`ui.js` 里
`if (f.width !== 'half') node.classList.add('field--full')`），漏掉它两个下拉就会
挤进网格的一列里 —— 光看代码看不出来，量宽度 358 vs 173 一眼就看出来了。

旧实现删干净之后就没得对比了，改用 `checkFormShape()`：把那一页表单的**金标准形状**
（标题、宽窄、字段顺序与半宽/整宽、控件类型、页脚按钮）写死在测试里，以后谁把字段挪走、
加宽、换个控件类型，当场红。现在**每一页都是这么盯的** —— 结构照样是量出来的，
只是参照物从「旧实现」换成了「上一次认可的结构」。

`npm run test:ui` 里还有几段是「这一页独有的钱」：组合报价的合计和复制出去的报价单格式、
阶梯价改动有没有落库、导出图片/Word 的文件名（把 `<a download>` 的点击截下来看，
不真往磁盘写）、财务页八个格子对不对得上接口。另外那些「不该漏的东西」也在里面：
订单详情记完收款要能对上 `已收`、删完要剩几笔，保险箱锁着的时候明文一个字都不能出现在
列表里，客户档案上点一张单要能进订单详情，乱敲地址要落到兜底页。

屏幕识别（OCR）这块测得到的是「状态能取到、契约不破」：后端快照在不在、引擎链顺序对不对、
依赖清单文件在位不在位、自检要么通过要么给得出能照做的原因（测试实例的 venv 在临时数据目录里，
所以多半走的是「给原因」那条路），以及装依赖/自检那几条路不会 500。
「装了引擎之后真的认得出」这件事得在装了引擎的机器上验 —— 用
`node scripts/vision-selftest.mjs` 和 `node scripts/vision-parity.mjs`。
