# 代肝价格查询 · 私用运营台

一个**单人自用**的代肝管理后台。不是商城，没有客户注册登录，没有多代肝入驻。
打开就是七个模块：游戏 → 服务与价格 → 客户 → 登录凭证保险箱 → 订单 → 进度记录 → 财务，
外加一个「报价单生成」。

后端继续使用 Node.js 原生 HTTP + SQLite，前端改为 React 19 + Vite 8，图标使用来自 GitHub 的 Lucide React。
业务数据和登录凭证仍全部存在你这台电脑上，依赖只用于构建前端，不参与数据托管。

---

## 一、跑起来

需要 **Node.js 22.12 或更高版本**（用到了内置的 `node:sqlite` 和 Vite 8 构建链）。
没装的话去 <https://nodejs.org> 下载 LTS 版本，一路下一步即可。

从源码运行时先安装依赖并构建一次：

```bash
npm run setup
```

日常开发可以开两个终端：`npm run dev`（前端热更新）和 `npm run local`（本地后端）。

| 系统 | 怎么做 |
| --- | --- |
| Windows | 双击 **`DaiganLauncher.exe`** |
| Windows（只给本机用） | `DaiganLauncher.exe --local` |
| macOS / Linux | 终端里 `./start.sh`，或 `./start.sh --local` |

启动后窗口里会打印两个网址：

```
本机打开：   http://127.0.0.1:8787
手机打开：   http://192.168.1.7:8787     （手机要和这台电脑连同一个 WiFi）
```

启动器里可以直接启动、停止、重启后台，也可以设置当前用户开机自启动。

端口被占用了就换一个：`DaiganLauncher.exe --port 8888`。

## 二、第一次用，按这个顺序

首次打开会引导你设三样东西：店铺招牌名、登录密码、保险箱密码。

然后建议按顺序录：

1. **价格表 → 新建价格表** —— 一张价格表 = 一个游戏。建的时候顺手把区服填上（逗号分隔），
   想好看还可以传个图标。
2. **在价格表里「新建大类」** —— 日常 / 周常 / 深渊 / 活动 / 材料 / 成就……
3. **在大类里「加服务项」** —— 每日委托、清体力、深渊 12 层……选一种计价方式，填单价。
   **服务项只能挂在大类里**，所以先有大类、再有服务项。
4. **服务项详情 → 阶梯价 / 套餐与增项** —— 数量大的（比如深渊层数）加阶梯价；
   加急、指定角色、不动原石这类做成增项。
5. **客户** —— 录第一个客户，手机号填上（它是客户的标识，以后直接搜手机号）。
6. **订单 → 开新单** —— 选客户、勾服务，价格自动算出来。

> 价格表页面的结构是 **游戏（一张价格表）→ 大类 → 服务项**。
> 服务项表单里的「游戏」和「大类」两个下拉是联动的：
> 换了游戏，大类列表只留这个游戏的和通用的；选了一个属于某个游戏的大类，游戏会自动跟着切过去。
> 这样就不会出现「游戏选崩铁、大类却是原神的日常」这种自相矛盾的价格项。

### 五种计价方式

| 方式 | 用在什么上 | 例子 |
| --- | --- | --- |
| 固定价 | 一口价的服务 | 周本全清 25 元 |
| 按天 | 包月、日常托管 | 每日委托 5 元/天 × 30 天 |
| 按次 | 一次一次算 | 清体力 3 元/次 |
| 按数量 | 数量越大越便宜 | 深渊 1~5 层 30/层，6~12 层 25/层 |
| 套餐价 | 打包一堆内容 | 活动全包 120 元/套 |

## 三、七个模块分别管什么

### 游戏管理
游戏名、简称、图标、区服列表、**货币名称**、排序、上架/归档、备注、**顶部提示**。

**货币名称**填这个游戏里客户最认的那种货币（原石 / 星声 / 纠缠之缘…）。
填了之后，服务项表单里就会多出一栏「可获得货币（星声）」，写这个服务项能给客户拿到多少。
一个游戏一种货币；没填就不显示，服务项上那个数也不会有单位。

**顶部提示**是对外给客户看的一句话（可以多行，一行一件事），和「备注」分开：

- 备注是你自己记账用的，**不会出现在导出里**；
- 顶部提示会出现在**导出图片 / Word / Excel 的最上方**（抬头下面、第一个大类上面），
  所以写之前想一下「这句话客户看到会不会有问题」。

导出多个游戏合并成一份时，顶部提示不会硬提到最上面（免得「鸣潮的提示」被当成整张表的说明），
而是各自跟在对应游戏的小标题下面。价格表页面里也会在游戏表头下面显示一遍。

界面上**不写「公告」这两个字**：提示条自己就说明白了 —— 应用里是靛蓝底纹 + 左边一道竖线；
导出（图片 / Word / Excel）统一成黑白灰，只留一条细灰竖线，不再铺底纹。
大类也有同款，见下面「两级提示」。

**删除是归档，不是真删。** 老订单里冻着游戏名，真删了档案就断了。
真要彻底删除，列表里也有那个按钮，但会先告诉你有多少订单和凭证挂着它。

### 服务与价格管理

价格表页面按 **游戏（一张价格表）→ 大类 → 服务项** 三层展开。
整页是按「一张价目表」来排的，不是按「一堆列表项」来排 —— 三级靠**字体、栏线和留白**区分：

```
鸣潮  官服                                  9 个大类 · 73 个服务项   [+ 新建大类]
═══════════════════════════════════════════════════════════════════════════
▌地图全收集 1230（星声 4.5W）                    ← 游戏的顶部提示（通栏）
▎日常  [每天做]  期间都会免费帮领取…  ──────────── ¥70 – ¥300  4 项
  ▌包月客户这个大类里所有套餐都能换着做。          ← 大类的提示（缩进、字小一号）
    单次下单按套餐算，不拆开卖。
    日体套餐                                      ¥70 /30天
    含 每日活跃+每日体力
▎探索 100%  按数量逐步定价  ──────────────────── ¥40 – ¥70  4 项
    瑝珑声匣 ············································· ¥50 /单
```

- **游戏表头**最大（大字 + 账簿双线），往下滚的时候**吸附在顶栏下面**，
  看一眼就知道自己在哪个游戏里；
- **大类**是中号字 + 前面一道朱砂刻度，名字后面一条栏线拉到底，
  右边坐着**价格区间**和项数 —— 所以收起状态也能扫一遍价位；
- **服务项**是账目行：名字在左、金额在右（等宽数字，一列对齐），中间点线相连；
- **管理按钮平时是收起来的**（鼠标进到那一行才出现），所以正文永远是一张能直接读的价目表。

#### 服务项能拿多少游戏货币

游戏上填了**货币名称**之后，服务项表单里就多一栏「可获得货币（星声）」，填这个服务项能让客户拿到多少。

- 客户视角：导出图片 / Word 里，这一行紧跟在服务名下面、说明文字上面 ——
  `可得 星声 240`，比说明重一档，说明被截断也不会把它挤掉；
  价格表页面和详情抽屉里是一个小标签（`星声 240`）。
- 归类规则：数量记在服务项上，**名字跟着游戏走**（服务项自己没绑游戏就跟大类走）。
  游戏没填货币名、或者服务项没填数量，就什么都不显示 —— 不会出现一个没有单位的数字。
- 一个游戏一种货币。留空 = 不显示。

#### 两级提示：游戏的排最上面，大类的排在这个大类里

游戏和大类都能写一条**对外提示**，都不用「公告」这两个字：

| | 写在哪 | 出现在哪 |
| --- | --- | --- |
| 顶部提示 | 游戏表单 | 整份价目表的**最上方**（抬头下面、第一个大类上面），通栏 |
| 大类提示 | 大类表单 | 这个**大类的名字下面**、服务项上面，缩进一格、字小一号 |

两处都跟「备注」分开：备注是你自己看的，**一个都不会进导出**。
图片、Word 和 Excel 用的是同一份模型，所以三边看到的排版和内容完全一致。

#### 大类也能归档 / 彻底删除

大类那一行鼠标放上去，操作组里最后一个是垃圾桶：

- **归档大类**：先从价格表里收起来，服务项、价格、阶梯价全部原地不动；
- **彻底删除**：大类没了，底下的服务项**不会跟着消失**，只会变成「未分类」，
  还能重新归到别的大类里。已经开出去的老订单也不受影响 —— 价格冻在下单那一刻。

两个都会先告诉你这个大类底下挂着多少个服务项，再让你选。

- **服务项必须挂在大类里**，所以新建服务项的入口只在大类行上，没有「直接建服务项」这条路。
- 每个服务项能改价、改说明、上架下架。
- 按数量计价的可以配**阶梯价**。
- **增项**可以挂在某个服务项下，也可以建成全局通用（比如「全程录屏」）。
- 没绑游戏的大类会归到「通用」组；早期没归到大类的服务项会落在「未分类」里，照样能改。

#### 没填备注和套餐内容的服务项，会自动压成一行

规则很简单，**只看这一个服务项自己填了什么**，跟它属于哪个大类无关：

- **没填备注、没填套餐内容、没挂增项、没有阶梯价** → 排成一行：
  `北落野 ························· ¥25/单`
  鼠标放上去才露出拖动把手和「详情 / 改」两个按钮（触屏上一直显示）。
- **填了上面任何一样** → 照常铺开成多行，把内容都显示出来。

所以像「8 个地区价」那种，填了备注的那几行是铺开的，只有名字和价格的那行是紧凑的，
不会再在行里留一片空白。

#### 大类和层级

**大类默认全部收起。** 一进价格表先看到的是「这张价格表里有哪些大类、各值多少钱」，
想看哪个再点开哪个，不用在一屏拉不到底的长列表里翻。谁点开过就记住谁（刷新页面也还在）。
往收起的大类里加服务项时会自动帮你展开，方便看刚加的那条。

收起状态下也**不是**只能看到名字：每个大类右边都有价格区间（`¥70 – ¥300`）和项数，
扫一眼就知道这个大类值不值得点开。工具栏上还有**「全部展开 / 全部收起」**一次到底。

为了让「大类」和「服务项」一眼分得清：

- 游戏是**表头**：最大号字 + 账簿双线，吸顶；
- 大类是**分组标题**：中号字、前面一道朱砂刻度，后面一条栏线拉到底；
- 服务项是**账目行**：名字左、金额右，中间点线，缩进对齐到大类名字。

#### 拖动排序

**服务项**和**大类**都能拖，两套互不干扰：

- **按住一个服务项拖** —— 调整它在当前大类里的位置；
  **拖到另一个大类里**，就等于同时把这个服务项换了归属（游戏也跟着大类走）。
- **按住大类的标题拖** —— 调整大类顺序；
  **拖到另一个游戏那一组里**，就等于把这个大类换了游戏。

拖动时会有一条朱砂色的插入线告诉你落在哪。

顺序存在 `sort_order` 上，拖完会把整份顺序写回数据库，
所以刷新、换设备看到的位置都一样。

排序基于完整数据而不是当前显示的内容，**所以开着搜索或筛选拖也不会漏掉没显示的项**。

> 拖动用的是浏览器原生的拖放，鼠标和触控板都好使；纯触屏（手机）上拖不了，
> 那种情况就在电脑上排一次，手机上照着看。

改价格表**只影响之后开的单**。已经开出去的老单冻在下单那一刻的价格上。

### B站自动比价（从别人的价格表视频里抄价）

定价最费劲的一步是「别人现在卖多少」。价格表右上角有个「**B站比价**」，
点开会去 B站 搜「`游戏名 代肝 价格表`」这类视频，下载、抽帧、逐帧 OCR 认价，
把认出来的价和库内服务项对上，**按多个视频取中位数**，出一张预览表给你确认。

选中一个具体游戏（标签栏里那个）之后按钮才亮 —— 比价是按游戏搜的。

**它怎么认的**

1. 搜视频（走 B站 的 wbi 签名接口，用「设置 → 媒体账号」里那个 B站 登录态）；
2. 下前 8 个视频，每个抽帧（默认每 3 秒一帧，最多 40 帧）；
3. 抽帧时顺手算一个 16×16 的灰度指纹，**和上一帧长得一样就丢掉** ——
   价格表视频大半时间画面是静的，这一步能省掉七八成的 OCR；
4. 每帧交给本地 OCR，得到带坐标的词，按 y 坐标聚成行；
5. 每行里找「名字 + 价格」，用一堆规则排掉不像价格的数字；
6. 认出来的名字和库内服务项做模糊匹配；
7. 同一项跨视频取中位数。

**扫过的视频不会重扫**

同一个关键词搜出来的视频高度重合，所以**第二次扫的时候大半时间本来都是白花的**。
现在每个视频的识别结果会留着，下次遇到同一个视频直接跳过「下载 → 抽帧 → OCR」
三步。AI 的判断也一起缓存。

实测同一个关键词连扫两次（4 个视频）：

| | 总耗时 | 下载/抽帧/OCR | AI 甄别 |
| --- | --- | --- | --- |
| 第一次（冷启动） | **100.6s** | 46s | 46s |
| 第二次（全部复用） | **4.0s** | 0.9s | 0s |

而且**结果是逐项一致的**（都是「认出 69 个名字、匹配 36 项、未匹 11 项」）——
缓存只省掉重复劳动，不改变结论。

几个要点：

- **跳过是按视频来的，不是全有全无。** 搜出来的视频每次都略有不同，所以真实
  使用中总是「有几个扫过、有几个没扫过」。实测「一半命中」时：复用 2 个、
  重扫 2 个、48 秒跑完，结果照样完整。
- **缓存的只是「原始识别结果」**（每一帧的 OCR 词），不是解析后的成品。
  解析那一步每次都重跑，所以**改了库内服务项、换了 AI 模型，下次扫描立刻生效**，
  不用等缓存过期。
- **AI 判断的缓存带签名**：模型 + 库内服务名 + 解析版本，任何一样变了就重新问模型。
  否则会出现「拿着旧库的判断套新库」—— 那是会写错价的。
- **重新识别过就一定清掉 AI 缓存。** AI 是按 `帧:行` 指认的，重扫后行号一挪，
  旧判断就安到了别的行上，等于随机删价（实测出现过「重扫后未匹配数从 9 变成 12」）。
- 缓存留 30 天，跟着中间产物的清理一起过期。
- 视频里的价格表改了、或者想换一批视频时，勾「**重新扫一遍**」，全部重来。

**为什么是「选择跳过」而不是自动判断该不该跳过**

系统没法知道视频里的价格表是不是变了 —— 那正是要扫描才能知道的。所以默认复用、
把选择权留给用户：想重扫就勾一下。反过来（默认重扫）就等于每次都要等一两分钟，
而那正是这个功能想解决的问题。

**新加的游戏：从扫描结果直接建服务项**

上面那些都建立在「库里有能对上的服务项」上。**新加一个游戏时库里一个服务项都没有，
比价必然 0 匹配** —— 这不是坏了，是没东西可以匹配。原神就是活例子：4 个大类、
0 个服务项，扫出来 71 个名字全部落在「没匹配上」。

所以扫描结果里多了一个「**建服务项**」标签页：

1. 点「让 AI 整理这份清单」；
2. AI 把认出来的名字**合并**（`全包箱` 和 `全宝箱+神瞳` 是同一样东西）、
   **起名**（`套餐①：至东国满探索100%探索+神瞳+前置任务+供奉` → `至东国满探索`）、
   **归类**（放进已有的大类）、**丢掉不是服务项的**（`改为`、`星期三`、`一月`）；
3. 名字、价格、大类都能改，勾选后一键建进库里；
4. **扫描到的价直接写成基准价**，下次扫描就能匹上了。

实测（原神，真模型）：57 个名字 → 55 条建议，AI 用 6.7 秒。它自己合并出了
`全宝箱+神瞳`（来自 `全宝箱+神瞳` 和 `全包箱`）和 `挪德卡莱满探索 ¥430`
（来自 `②挪德卡莱前置+满探索+神瞳` 和 `挪德卡莱满探+前置任务+神瞳`）。

**AI 在这里碰不到价格。** 输出里根本没有价格字段；价格是程序按来源行自己算的
中位数，和正式匹配那边同一套规则（**同一个视频给了两个不同价就整票弃用**）。
理由和甄别那一步一样：价格错了会开错单，而且在界面上看不出来。
AI 编出来的名字也必须能对应到扫描里真的出现过的名字，否则整条丢掉。

**别名：为什么改了名字下次还能匹上**

视频里写 `挪德卡莱满探+前置任务+神瞳`，你价格表上想写 `挪德卡莱满探`。
但前者含 `+`，被判定成**打包价**，按规矩只认同名服务项（这是为了防止把一个
打包价摊给单项）。所以短名字**永远**匹不上 —— 除非把原话记下来。

建服务项时会把**视频里的原话记成别名**，正式名字和别名一起参与匹配：

| 你建的名字 | 记下的别名 | 下次扫描 |
| --- | --- | --- |
| `挪德卡莱满探` | `挪德卡莱满探+前置任务+神瞳` | ✓ 靠别名匹上 |
| `挪德卡莱满探+前置任务+神瞳` | （不用记，名字就是原话） | ✓ 同名匹上 |

别名在「服务项」表单里能看、能改（一行一个）。手工维护也有用：视频里那种
长写法填进去，下次就自动对上了。

顺带修了一个相关的老毛病：`effectiveName` 会把 `套餐①：至东国满探索…` 削成
`套餐①`（「名字：说明」这条规则对 `日体：5R/天` 是对的，对 `套餐①：…` 就把真名字
削掉了）。现在**原话也能参与匹配，但只认完全相等** —— 拿原话做模糊匹配的话，
`全包：主线+前置+全宝箱` 会误匹到库里的「主线」。

**为什么不猜**

价格是这个系统里最不能出错的数据，所以宁可少给一条，也不给一条错的：

| 情况 | 怎么处理 |
| --- | --- |
| 一个视频里同一项给了多个价 | 整个视频的样本**都丢掉**，写明「同一个视频给了多个口径」 |
| 计价单位对不上（视频是「天」，库内是「30天」） | 丢掉，写明单位不同 |
| 名字匹配分低 | 只在没有更好的样本时用，并标上「低置信」 |
| 打包价（`珑十一图+黑海岸全图探索 400`）没带 `/单位` | **不摊给单项**，单独列在「没匹配上」里 |
| 样本数不够（默认少于 3 个） | 照常给中位数，但标「样本不足」 |

**每一步都能核对**

预览表里每一行都能展开，看到：

- 参与计算的**每个样本**：价格、认出来的原文、来源视频（可点开）、**来源帧原图**；
- 被剔除的样本**和剔除原因**；
- 价格的四分位距（散不散）。

点来源帧的缩略图能看原图 —— 这是核对 OCR 有没有把数字认错的唯一办法。

**扫完关掉了，还能再看**

任务本来就存在库里。再打开这个抽屉时，如果当前没有在跑的任务，它会自动把
**这个游戏最近一次扫出结果的那一回**捞回来，并在上面写一行「这是 N 分钟前那次
扫描的结果，不是刚跑的」—— 不用为了再看一眼重扫一遍（重扫要再等一两分钟、
再下几十兆视频）。

捞回来的结果**一行都不默认勾选**：这是「回头看看上次扫出了什么」，不是「接着写
上次的结论」，默认勾上容易手一滑又写一遍。已经写过的行会标「已写入 239」，
提醒你库里其实已经是这个价了。

**写入**

底部只写你勾中的行，而且**只改基准价**，不动阶梯价和增项。
勾选状态默认只勾「样本够」的那些，其余自己挑。
涨跌超过一倍的会标「幅度大，请核对」。

**机器认错了怎么办（改派）**

服务名那一格是个下拉框，不是死字。机器靠模糊匹配认名字，总会认错
（`黎那汐塔` 能靠编辑距离匹到别的项上）—— 没有改派的话，你面对一条认错的行
只有「丢掉」一个选择，可价格明明是对的，只是挂错了地方。

改派之后，左边那个「现价」会跟着换成**目标服务项**的现价 ——
显示的和实际要覆盖的必须是同一个值，否则你看着 A 的现价、写的却是 B。
改派过的行左边有一条琥珀色竖线，并标「已改派」。

两行被改派到同一个服务项时，两行都标「撞项」、底部写明，写入按钮直接禁用 ——
后写的会盖掉先写的，这种事必须当场拦住，不然你以为写了两项、实际只落了一项。

**认出来但库里没有的项**单独列在「没匹配上」那一栏，
可以照着那个价先去「添加服务」把项建出来，下次扫描就能自动对上了。

**大类候选（视频里的板块名 → 价格表的大类）**

价格表视频是按板块排的，板块名就是你的大类：

```
地图探索                    ← 板块名，本身没有价格
全图全收集1230（星声4.5w）
珑满探索300全收集350（星声1.3w）
```

扫描时会把这些板块名一并认出来，聚合成「大类候选」列在一个单独的标签页里，
勾几个一键建出来、挂在当前游戏下。**只建大类，不建服务项** —— 大类就是一个
名字加一个游戏，而服务项要选计价方式、单位、是否每天做，视频里没有可靠信息
（`238包月` 到底算 fixed 还是 daily？），猜错了比不建更麻烦。

候选里会标出「已经有了」和「像『托管』」：后者是模糊判重 —— `托管类` 和已有的
`托管` 明显是同一个东西，`罗伊冰原地图` 和 `罗伊冰原` 也是。工具栏那个
「勾上不重复的」就是一次勾上所有既不同名、也不像已有大类的候选。

判据是「这行**没有被认出价格**，长度 2~10 且八成以上是汉字，冒号只能出现在
结尾，后面 4 行里至少有 2 行有价格」。这套判据是拿磁盘上**所有真实帧**跑出来
调出来的，因为价格表视频里到处都是「没有价格、后面紧跟着价格」的行：

| 陷阱 | 实际长什么样 | 靠什么挡住 |
| --- | --- | --- |
| 换行的服务项 | `第二幕：为了没有眼泪的明天` + 下一行 `15r` | 冒号在中间而不是结尾 |
| 说明句 | `包含危行任务+探图活动`（后面紧跟 3 条有价行） | 说明句特征词 |
| 关键词列表 | `探索度 锄地 声骸 地图任务深渊等` 折行后的下半截 | 结尾的「等」 |
| 播放器按钮 | `退出`、`充电烫TA` | 界面词表；结尾只剥标点不剥字母 |
| 文档界面 | `格式刷粘贴 正文 标题1 标题2 样式集` | 界面噪音词表 |

反过来，标题本身允许三种装饰，都会先剥掉再判：版本前缀
（`3.5版本梦州地图` → `梦州地图`）、序号前缀（`一：托管类：` → `托管类`）、
结尾箭头（`梦州地图←`）。

想看看手里这批视频现在能认出哪些标题，可以拿磁盘上已有的帧 dump 一遍
（需要 5419 上有视觉后端；脚本在 gitignore 的 `data/bili-tmp/` 里，属于调试工具）：

```bash
node data/bili-tmp/t-sections.mjs 14 4     # 最多 14 个任务、每个视频最多 4 帧
```

**AI 甄别（可选，但强烈建议配）**

价格表视频里混着主播口播、聊天记录、播放器界面、文档工具栏。实测最近 12 次扫描
认出来的 168 个名字里，约 **22% 根本不是价格**：

```
改为                        ¥60     ← 文档编辑界面的词
星期三                      ¥25     ← 聊天里的星期几
我一窍不通                   ¥860    ← 主播在说话
然后我看了一下同行的价格 ISI 19.8  ¥13     ← 主播在说话
查找整换 AI8版 版 智能         ¥2      ← WPS 界面
```

规则判不了这件事，因为判据是**语义**的：`改为`、`星期三` 单看都是正常的词。
接一个模型就能判。填 OpenAI 兼容的 `base_url` + `model` + `key`（DeepSeek、
OpenAI、中转站、本地 ollama 都行），点「测试连接」确认通了就生效。

**模型碰不到价格 —— 这是硬约束，不是靠叮嘱**

| 怎么保证 | 在哪 |
| --- | --- |
| 输出的 JSON schema 里**根本没有价格字段** | `DECISION_FIELDS`，模型没地方放数字 |
| 拿回回复后只按白名单取字段，多出来的一律丢 | `pickFields()` |
| 价格自始至终来自 OCR 原文 | `candidate.price` 从没被 AI 碰过 |
| 拼 prompt 时只说「这行有价」，不说「是 60 元」 | `buildTranscript()` |

冒烟测试里有一条专门的用例：让假端点返回带 `price: 99999` 的回复，
断言这个字段到不了业务逻辑。还有一条：同一批帧跑两遍（开 AI / 不开 AI），
断言**开 AI 后出现的每个价格，不开 AI 时也出现过** —— 一个都不许多。

**推理模型会把这个功能搞坏（一定要看）**

如果你的模型是推理模型（`deepseek-reasoner`、`o1`/`o3`、名字里带 `thinking`/`reasoner`
的，或者像本机在用的 `deepseek-v4.1-flash` 这种「思考 + 回答」两段的），注意这件事：

**它会把 token 额度花在「思考」上，正文返回空字符串。** 实测一个视频的甄别请求：

```
prompt_tokens: 2843   completion_tokens: 2500
reasoning_tokens: 2500        ← 全部额度都花在这儿了
content: ""                   finish_reason: "length"
```

那段思考还是散文式的逐行纠结，甚至开始揣测「出题人想看到什么」，从头到尾没写出 JSON。
整批判断因此作废。

已经处理了三层，正常情况下你不需要管：

1. **主动关掉思考。** 各家叫法不一样，所以一次发三个
   （`reasoning_effort:'none'` / `thinking:{type:'disabled'}` /
   `chat_template_kwargs:{enable_thinking:false}`），认得的照做、不认的忽略；
   哪个网关不认到直接 400 的，会自动把它剔掉重试。实测能把推理 token 压到 0。
2. **额度跟着输入走**，不写死。一行判断几十个 token，几百行的视频给固定 4000 会不够。
3. **万一还是被截断**，会自动把额度翻三倍重跑一次，而不是直接放弃。

如果还是失败，报错会明确说清是哪一种（被截断 / 正文空但思考里有东西 / 地址不是
OpenAI 兼容），而不是给你一句没头没尾的「没给出 JSON」。**扫描结果页也会显示**
—— 「AI 这一步没成功」加原始错误，因为「界面上写着配好了、实际一次都没成功」
比直接报错更坏。

**AI 只做五件事**
1. **行级甄别** —— 这行是不是价格表里的一项。真正的危险不是垃圾出现在预览里
   （那看得见），而是垃圾的名字碰巧撞上库里的服务项把中位数拉垮：`每日委托 ¥2`
   （其实是「每天 2 元」）撞上库里的 `每日委托`，建议价就从 300 变成 2，
   而这种错**在界面上完全看不出来**。
2. **口径判断** —— `基础日常：一天 3` 是每天 3 元，库内 `日常托管` 是 300/30天。
   两个数取中位数毫无意义。判据是**不对称**的：`total`（一次性）永远放行，
   带周期的只有库内周期同一种才放行。所以模型把一次性误判成 total 只是「没挡住」，
   不会误删真价。
3. **名字纠错** —— 把 OCR 认歪的写法换成库里的写法（`声厘`→`声匣`）。
4. **兜底匹配** —— 规则匹不上的，让模型**从库内候选里选**（`service_id` 不在候选里
   一律当没选），它编不出一个库里不存在的服务项。
5. **抽「包含内容」** —— 视频里写的 `精托套餐（日体+期间活动+千道门扉）`，把括号里
   那句抽出来，写价时可以选择补进服务项的「包含内容」。

第 5 件**默认不勾**，得自己在写入前点一下。写价格是改一个数，写「包含内容」是改
**给客户看的文案** —— 价格写错了数字摆在那儿立刻能发现，文案被塞进一句视频原话
可能要等客户来问才发现。而且只**追加不覆盖**：库里已有的内容一个字都不动，
要去重（已经有一句覆盖了它就不再加）。抽错了最多是多一条冗余，不会毁掉已有内容。

**两道防「AI 帮倒忙」的闸**

调这个功能时踩出来的，都留了回归测试：

- **改名必须是「纠正」不能是「重写」。** 一开始的 schema 是「一行给一个名字」，
  结果一行有两个候选时（`黑海岸群岛20 泰缇斯之底20`）两个候选被塞了同一个名字
  `黑海岸群岛、泰缇斯之底` —— 匹配率从 34 项掉到 6 项，而且界面上看不出来是
  AI 干的。现在改成**按名字给**（`renames: [{from, to}]`）。
- **「库里有这个名字」不能单独当作放行理由。** 库里有 `瑝珑梦州 满探索`，模型就
  把 `梦州全收集` 和 `梦州全包` 也改成了它 —— 三个不同套餐挤成一项，价格会被
  混着取平均。库里有只说明**目标合法**，不说明**这次改得对**。现在要求
  「OCR 名字里就含库内那个名字」（`精托套餐：日体套餐+…` → `精托`，这是托管类
  最常见也最可靠的一种）或者「确实像」。
- **AI 说删，但和库内某个服务项完全同名 —— 不删。** 假端点把
  `黑海岸群岛 ¥20`、`虎口山脉 ¥20` 判成了噪音，三项因此失去建议，
  而用户**看不到自己失去了什么**。漏留的垃圾看得见，删掉的真价看不见。

改名的门槛是**故意偏保守**的，这里有个明确的不对称：拒掉一个本该接受的改名，
代价是那一行落到「未匹配」里、你点一下改派就行 —— **看得见、能挽回**；
接受一个不该接受的改名，代价是几个套餐的价格被混在一起算出个错价 ——
**可能看不出来**。所以像 `黎娜西塔全图探索 → 黎那汐塔` 这种（OCR 把 `那` 认成
`娜`）有时会被拒，但它会被**兜底匹配**那一步接住（实测真扫那次兜底匹上 11 个）。
改名只管机械纠错，语义对应交给兜底 —— 两层分工。

**AI 挂了会怎样**：原样走规则管线，什么都不少。没配 key 就完全不会调用。
任务结果里的 `ai` 字段记着这次剔了几行、纠了几个名、拦了几次误删，
界面上也能展开看具体是哪些行 —— 每个判断都可核对。

想在没有 API key 的情况下验证整条链路，可以用仓库里的假端点
（`data/bili-tmp/t-ai-mock.mjs`，它真的解析 prompt、按帧号行号逐行回判断）：

```bash
node data/bili-tmp/t-ai-mock.mjs 5999 &
XFC_AI_BASE_URL=http://127.0.0.1:5999/v1 XFC_AI_API_KEY=test XFC_AI_MODEL=mock \
  node data/bili-tmp/t-ai-replay.mjs <任务id> 鸣潮
```

`t-ai-replay` 是**同一批帧、同一份 OCR 结果跑两遍**的严格对比。为什么不能用
「扫两次对比」：B站的搜索结果每次都会变，两次扫到的视频不同，结论不可比
（我一开始就是这么比的，34→6 看着像灾难，其实是换了视频）。

**需要装什么**

下载视频要 **yt-dlp**。第一次点开会检查环境，缺了可以一键装到项目自己的
Python 环境里（`data/vision-venv`，和屏幕识别共用一个）。
**ffmpeg** 没法自动装（各平台分发方式差太多），要自己装好并确保在 PATH 里。
OCR 用的是屏幕识别那套本地引擎。

中间产物（视频和帧）放在 `data/bili-tmp/`，超过 24 小时会在下次扫描时顺手删掉。

### 导出价格表（图片 / Word 文档 / Excel 表格）

价格表右上角有个「**导出图片/文档**」。点开是这样一个面板：

```
导出范围    [每个游戏各出一份（推荐 · 分开的文件） ▾]
带说明文字  ☑     联系方式 [微信：xxx]   页脚说明 [价格随版本更新…]

预览  ┌──────────────┐
      │  渲染好的图片  │      ← 改任何选项，预览实时重画
      └──────────────┘

[关闭]        [生成 Excel 表格]  [生成 Word 文档]  [生成图片]
```

**默认按游戏拆开，一个游戏一份文件，不会把几个游戏混在一起。** 发给客户时只发他那款游戏那份。
如果确实想要一张总表，把「导出范围」改成「全部游戏合并成一份」就行。

- **图片**：PNG，1080px 宽、2 倍图（实际 2160px），直接发微信、发朋友圈都清楚。
- **Word**：真正的 `.docx`，Word / WPS 都能打开和二次编辑。A4 完整价目册，真实表格、阶梯价逐档列出。
- **Excel**：真正的 `.xlsx`，**一行一个价格档，单价是能排序、能求和的真数字**；
  首行冻结 + 自动筛选，多个游戏各一张工作表，适合自己改价、对账或者二次统计。
- **三者内容完全一致**——都从服务端同一个导出模型生成，不是三套逻辑各画一遍。

**配色只有黑白灰**：近黑 + 两档灰，一个彩色都没有。层级靠字重、字号和留白表达，
所以没有顶部色条、没有彩色底纹、没有大类色块，也没有「服务名 ······ 价格」那种点线。
提示（公告 / 大类提示）只保留左边一条细灰竖线。三个导出文件用的是同一组色值。

导出会自动裁掉多余内容，目的是**一张图一眼能看完**，不是把整张价格表塞进去：

| 裁掉什么 | 怎么处理 |
| --- | --- |
| 已下架的大类 / 服务项 | 不导出 |
| 空的大类 | 不导出 |
| 每个大类超出条数的服务项 | 折成「…… 这个大类还有 N 项」 |
| 超出数量的大类 | 折成「…… 还有 N 个大类没有列出」 |
| 过长的说明 | 截断成一行 |

导出是**跟着数据结构走**的，以后你新加什么都会自动带上，不用改代码：

- 新游戏 → 自动多出一份（Excel 里是多一张工作表），并带上游戏小标题
- 新大类 / 新服务项 → 自动进对应分组
- **阶梯价** → 转成提示，例如「1-5层，最多到 ¥25/层」；Excel 里一档一行
- **增项** → 写进说明，例如「增项：加急 +20%、指定角色 +15元」
- **套餐内容** → 写进说明，例如「含 每日活跃+每日体力+周本」
- **没归到大类的服务项** → 不会静默丢掉，会落到「未分类」里一起导出
- 起订量 > 1 的 → 标出「起订 N 天」

### 客户管理
昵称、**头像**、手机号、微信、QQ、来源、标签、备注。点进客户档案能看到他的全部订单、收款流水、
登录凭证、报价单，以及累计金额和欠款。

**头像**选填，传一张图（1.5MB 以内）就行 —— 会显示在客户列表、客户档案页和订单列表的客户格上。
客户多了、重名了、或者名字很像的时候，一眼就能对上人。没传头像的用昵称首字当占位。

客户反复下单也不会乱：

- 客户档案里**先列在做的、已结束的收在后面**，各自封顶，多的折成「还有 N 张…」。
- 订单列表的客户格标出这是他的**第几单**，回头客一眼看得出。
- 订单页可以**按客户排**（同一个客户的单聚在一起），也可以点客户名直接进档案。

### 订单管理
下单那一刻会把**快照**冻住：客户名、游戏名、服务名、单价、数量、总价、
套餐内容、增项、下单时间。之后你改价格表，这张单一个数字都不会变。

#### 挑服务（下单台和报价单里都有）

```
挑服务                                        勾上就进单
[搜服务名…]  [全部游戏 ▾]  [全部大类 ▾]

▎日常                                          4 项      ← 分类标题吸顶，滚到哪都知道在哪
┌──────────────────────────────────────────────────┐
│ ☑ 活跃套餐                              ¥25/30天  │      ← 勾上的行整条提亮，左边一道朱砂
│   固定价                                          │
│   [2] 30天   [改价] 元                            │
├──────────────────────────────────────────────────┤
│ ☐ 日体套餐                              ¥50/30天  │      ← 没勾也看得到价格
│   固定价 · 周本可指定                              │
└──────────────────────────────────────────────────┘
[2] 已选                                    清空
```

- **可以按大类筛**。搜索、游戏、大类三个条件是「都要满足」，一起用。
- **大类列表跟着游戏走**：选了游戏就只列这个游戏的大类（加上通用的）；
  选过的大类要是不属于新游戏了，会自动退掉，免得筛出个空列表。
- **筛了游戏就自动选大类**：这个游戏只有一个大类时（大多数情况就是这样）
  直接选中它；有好几个才留给你自己挑。以前筛了游戏还停在「全部大类」，
  得再点一次下拉 —— 那次点纯属白点。

#### 一单可以混几个游戏，游戏是**推出来的**，不用手选

开单台上没有「游戏」这个下拉了。两头的事以前分在两个控件上，而且各管一半：

```
[游戏 ▾]           ← 只是存进订单头，并不过滤服务项
[全部游戏 ▾]       ← 真正过滤服务项的是挑服务区这个
```

于是用户会合理地以为「上面选了异环，下面就该只剩异环的服务」—— 结果列表没变。
现在改成：**明细说了算**。

- 挑服务的时候照常用挑服务区的「按游戏筛选」筛选（它只管筛选）。
- 单据头上那一格是**只读**的，随挑中的服务项自动显示：
  挑一个游戏的服务就写这个游戏；混着挑两个就写 `鸣潮 + 异环`。
- 提交时**不发游戏字段**，由服务端按明细里的服务项推；推不出来才用表单上旧的。
- 一单混了多个游戏时，订单头的 `game_id` 存 **null**（按游戏筛选那张列表
  不能撒谎说这单只属于某一个），`game_name` 存拼起来的那串。
- 快照照旧在下单那一刻冻住，推出来的游戏名也一起冻。

#### 资源/进度按服务项的游戏**分开记**

一单混了两个游戏时，记进度那张表单会**按游戏分块**填：

```
资源变动
【鸣潮】星声 [2174] 体力 [255] 贝币 [2508319]     ← 一个游戏一块
【异环】甲硬币 [929484] 方斯 [4116889] 环石 [3087]
```

- 存进库里的是一行带 `【游戏】` 标记的文本；**只有一个游戏时不加标记**，
  和以前存下来的老记录、老报表完全一样（老数据一条都不用动）。
- 时间线上的「本次消耗」也按块各算一次：两个游戏都有「体力」时不会混成一个数。
- 识别画面也是按块来的：每一块的「看画面」只认这个游戏的资源，
  不会拿异环的模板去鸣潮的画面上找。
- 分类标题**吸顶**，滚到哪儿都知道自己在哪个大类里，右边标着这个大类有几项。
- **价格常驻显示**，不勾选也知道多少钱。
- 底部固定一条「已选 N 项」，旁边有「清空」。
- **筛掉不影响已勾的**：勾好、填好数量之后再换筛选条件，勾选和数量都还在，
  合计也照常算着它们。
- **增项里标了「默认选中」的，勾上这个服务项就自动带上**，不用每次手动补勾
  （价格表里那个「默认选中」的勾才算数）。

#### 订单上也看得到「可得货币」

游戏上填了货币名、服务项上填了数量之后，**开单的全过程都能看到能拿多少**：

- **挑服务时**：服务名旁边一个小标记 `星声 13000`，挑的时候就摆在眼前；
- **金额汇总里**：多一行「可得 · 星声 15000」，勾几个就自动加（同一个货币才合计，
  跨游戏混了两种会分着写，不硬加）；
- **订单详情 · 服务明细**：每条下面一行 `可得 星声 26000`；
- **服务明细的面板底部**：`共 3 项 · 可得 星声 28000 · 合计 ¥700`。

数量和货币是**相乘**的：一条 `300/单 × 2` 的服务项，可得就是这个服务项的两倍。

**和价格一样冻在下单那一刻**：快照里存的是「每个的数量」，之后你在价格表上改了数字，
这张老单还是当时说好的那个数。老单（加这个功能之前开的）没有这段数据，就不显示这一行。

#### 交付日期会按「每天都做」的服务项自动算

单子里勾了**每天都做**的服务项时，**交付日期自动填成「下单日期 + 这个服务项的天数」**：

```
下单日期 [2026/09/23]        交付日期 [2026/10/23]      ← 自动填的
▌剩余 30 天   下单到交付 30 天   按「日体」30 天自动填的，可以直接改
```

- 天数怎么推：单位写成 **`30天`** 就算 30 天（你库里日体/精托/全托都是这种写法）；
  单位是 **`天`** 就按数量算；**按天计价**又没写单位的也按数量算；
  单位是「单 / 次 / 层 / 个 / 套」这种推不出来的，就**不自动填**，留给你自己填。
- 勾了好几条每天都做的，取**最长的那个**天数。
- 数量改了（比如 2 份 = 60 天），交付日期跟着挪。
- **你自己动过交付日期，就不再自动改**；把日期**清空**就等于交回给自动。
- 把那几条每天都做的都取消勾选，交付日期会跟着清掉。

不要这个自动？把服务项或它大类的「每天都做」摘掉就不算了。

#### 今日已完成（日体、包天这种天天要做的单）

日体、包天这类单**每天都要做**，做完就整单标「已完成」是不对的 —— 明天还得接着做。
所以订单详情页上有一个**「今日已完成」**：

- 点一下，这张单这个「今天」就**从「在做」列表里挪走**（看板的「进行中调度」也一起挪走），
  但状态还是「进行中」，钱和进度都没变。
- **过了凌晨 4 点它自己回到「在做」列表**（是 **4 点，不是 0 点**）——
  干到后半夜的人，凌晨 1 点做完的日体应该还算当天。不用做任何操作，也没有定时任务：
  标记时存的是**那个工作日的日期**，日期对不上就自动失效。
- 标错了、想今天就接着做 → 详情页按钮变成**「撤销今日完成」**，点一下回来。
- 想找这个「今天」标过哪些 → 订单页有个**「今日已完成」**筛选档。
- 已经真正「已完成」或「已取消」的单不给标（会提示）。

同一页上还有一个**「标记完成」**，那是**整张单结束**（永不再出现在「在做」里）。
状态机允许才会出现这个按钮 —— 还没确认 / 还没付款的单，得先走完前面的状态。

##### 哪些算「每天都要做」

**标在大类上**，不在单个服务项上：

- 名字里有**日常 / 日体 / 包天 / 每日 / 托管**的大类，建的时候**自动勾上**，
  以后新加的大类也认得出，不用手动设。
- 也可以在**大类表单**里手动勾 / 取消，价格表的大类标题上会显示「每天做」标记。

所以**以后往「日常」大类里加新的服务项，自动就算每天做** ——
哪怕那个大类和服务项是你明天才建的。

如果某个服务项要跟大类不一样（比如日常大类里的一次性附加项），
在**服务项表单**的「每天都做」里选「是 / 否」单独覆盖；默认是**跟随大类**。

##### 一张单里混着日常和一次性的活怎么办

比如「30天日体 + 两个活动」。两个办法，看你想要哪种：

**① 拆单**（订单详情右上角「拆单」）—— 把一次性的活挪到一张新单上，
两边**各自收款、各自结单**，互不牵扯：

```
DH260921-001  30天日体 + 两个活动     ¥130
        ↓ 拆单（勾上那两个活动）
DH260921-001  30天日体                ¥50     ← 天天标「今日已完成」
DH260922-002  30天日体（拆出）        ¥80     ← 自己走完成 / 收款
```

钱怎么分，规则是**说清楚**的：

- 每个服务项自己的金额（含它的增项）**跟着它走**；
- **折扣 / 手续费 / 成本留在原单**，新单从 0 开始（拆完可以各自再改）；
- **收款**在弹窗里选：
  - **按金额比例分到两张单**（默认）—— 已经收过的钱按两张单的新金额拆开，
    两边**各自结清**，加起来正好等于原来收的那笔（零头留在原单）；
  - **全部留在原单** —— 原单会变「多收」，拆的时候会提醒你多收了多少钱。
- **进度时间线**在弹窗里选：**留在原单**（默认）或**跟到新单**。
  进度是一段自由文字，没跟具体服务项挂钩，所以只能整批走或整批留。
- 客户、游戏、下单日期、交付日期、状态都照抄过去；标题会标「（拆出）」、备注写「拆自 DH…」。
- 原单必须**至少留一个**服务项，不能全拆走（整张都要挪的话，直接改那一张就行）。
- 拆出来的那笔收款也会标「拆自 DH…」，收款流水里能看出它是怎么来的。

> 收款和进度这两个选项只在**这张单已经记过收款 / 进度**时才出现，没记过就不问。

**② 不拆，直接标「今日已完成」** —— 点的时候会**先提醒你**，
把这张单里除了日常之外的活列出来（`若梦仍有回声、群声共振模拟域`），
让你确认这些也做完了。全是日常的单不会弹这个提醒，一步就标上。

订单详情的「服务明细」里，每天做的那条会带一个**「每天做」**标签，一眼看得出哪部分是日体。

#### 客户手机号

订单列表的客户格里直接显示**手机号**，要联系客户不用点进档案。客户头像、手机号、
「第 N 单」都在同一格，客户多了也能一眼对上人。

状态流转：

```
待确认 → 待付款 → 进行中 → 待验收 → 已完成
   ↘        ↘        ↘        ↘      ↓
              取消 / 售后 ←──────────┘
```

未按顺序跳转会被拦下来。**收款收满会自动从「待付款」推进到「进行中」**，省得再点一次。
已经记过收款的订单不允许直接删除（会让账对不上），要删得再加 `force`。

### 进度记录
每张单下面一条时间线：日期、完成内容、资源前后对比、截图/录屏链接、备注。
改了状态也会自动补一条进去。客户问「做到哪了」直接把那条发给他。

时间线按**一叠卡片**排（重做过一版）：

- 日期左边一列，写「**今天 / 昨天 / 3 天前**」，后面跟一个绝对日期（`10月2日`）——
  相对日期好扫，绝对日期是证据；
- 轨道上的圆点**按顺序点亮**：最新一条实心带光晕，更早的是空心 —— 一眼看出「现在做到这」；
- 「做之前 → 做之后」是并排的两个数，下面再给一排**本次消耗**的数字片
  （`星声 −160` 这种，消耗偏红、增长偏绿），不用自己心算；
- 截图做缩略图网格，点开大图；录屏/图床链接单独一排。

**「分享进度」按钮**（在进度时间线右上角）会把整条时间线整理成一份汇报，两种形式：

- **图片** —— 一张竖图，暖纸底 + 朱砂栏线，和价格表那张图同一套视觉，直接发微信。
  带单号、游戏、状态、已收 / 还差、每条进度的日期和资源变化（`160 → 40`）、备注。
- **文字** —— 同样内容的纯文本，点「复制文字」就能粘到微信里，想改两句就改。

截图原图塞不进这张图里，图上只会写「附 N 张截图」，图还是自己另发。

看板还会把**两天没记进度**的在做单挑出来提醒你。

#### 记进度时不用手抄资源数字

「记一条进度」里的**资源对比**两栏都有两个按钮：

- **自动识别** —— 点击后切回鸣潮窗口，按 **B** 打开背包识别贝币和星声，
  按 **ESC** 返回后再按 **M** 识别体力，最后再按 **ESC** 回到游戏。
  场景背景不需要和固定截图一致；程序以是否识别到贝币和星声来确认背包已打开。
  每个数字要**认到两次以上**才填进来。每页最多扫八帧，仍有缺项就按 ESC 返回并停止；
  **认完之后会自动把浏览器切回前台**，不用再手动 Alt+Tab 回来看结果（见下）；
- **识别截图** —— 选一张游戏截图，这次**直接拖整张图进来就行**
  （以前要压到 1.5MB 以内，现在 12MB 以内都收）。

自动切回默认按鸣潮窗口标题和安装路径查找；如果你的游戏进程名称特殊，可在启动前设置
`XFC_GAME_PROCESS` 为进程名（不带 `.exe`），再重启本程序。

**流程结束时为什么会自己切回浏览器**：切到游戏那一步（`scripts/focus-game.ps1`）
会先记下**当时在前台的那个窗口句柄**再抢焦点 —— 那正好就是你点「识别画面」的浏览器，
然后一起返回给 Node。认完（或报错）之后前端调 `POST /api/ocr/screen/return`，
`scripts/activate-window.ps1` 把前台还给这个句柄。

这么做而不是「按标题找浏览器」，是因为它不挑浏览器、不怕标题变、也不怕你开了几个标签页，
而且语义上就是字面的「返回」。几个刻意的取舍：

- **只在流程最末尾切一次**，不是每读完一页就切 —— 中间还要继续按 M 读下一页，切早了就白切；
- **失败只提示、不算失败**：数据已经认全了，纯粹是省一次 Alt+Tab。所以切不回来时只多一行
  琥珀色提示（`没能自动切回浏览器：…`），**不会**把「三项都识别到了」降级成失败
  （对比：没按成 ESC 是 `escError`，游戏界面可能还开着，那个才降级）；
- 切回去之后句柄就作废了（`nothing_to_return_to` 直接当成功返回），下次识别会重新记一个；
- 浏览器中途被关掉就是 `window_gone`，提示你手动切一下，不会有别的副作用。

连着记的时候，「做之前」会自动带上一条的「做之后」，不用重抄一遍。

它认的是**图标**、不是坐标，所以换分辨率不会散架：1280×800 到 3840×2400 全都认对
（下面「七、屏幕识别」一节有实测表，也有超宽屏那个真实上限的说明）。

认不出来时**不会瞎填**：宁可留空。想让认得更全，可以在**设置 → 屏幕识别**里
装一个本地 OCR 引擎（下面「七、屏幕识别」一节有说）。

**收款类型**有四种：**定金 / 全款 / 尾款 / 退款**。
第一次收款默认选「全款」（一次付清最常见），已经收过一部分再记就默认「尾款」。

### 财务
按时间段看：订单额、总收款、退款、净收、应收余额、平台手续费、成本、利润。
还有每日开单柱状图、按支付方式分组、按游戏分组、未结清清单、收款流水。

口径：订单额按**下单日**归集，收款按**到账日**归集，两者不必同月。
利润 = 订单额 − 平台手续费 − 成本，不含你自己的人工。

### 报价单
勾服务 → 价格自动算 → 实时生成一张报价单，可以**一键复制成文字发微信**，
也可以存下来。客户点头后，报价单**可以直接转成订单**。

## 四、保险箱的规矩

这是整个后台最敏感的地方，规矩是硬的：

- **优先扫码登录。** 能不存密码就不存密码——登录方式选「扫码登录」时，
  这条凭证可以一个密码字段都不填。
- **密码绝不存明文。** 账号、密码、密保、备注整块用 **AES-256-GCM** 加密后写进数据库。
- **密钥不存在任何文件里。** 它由你的「保险箱密码」用 scrypt（N=32768）推导出来，
  只活在服务器内存中。服务器一重启、你手动落锁、或者闲置 20 分钟，密钥就没了。
- **查看和复制要过第二道门。** 保险箱没解锁时，列表里只显示脱敏提示（`wa*****@qq.com`），
  内容是一张「封」条。要看明文得先输独立的保险箱密码。
- **谁、什么时候、看了哪条，全部留痕。** 「取用记录」里连解锁失败都记。
- **不存短信验证码、不存临时密码。** 那些一次性用完就该消失。
- **改保险箱密码会重新加密所有凭证。** 改之前建议先导出一份备份。

> ⚠️ **忘了保险箱密码就真的解不开**，没有后门、没有找回。请记在密码管理器里。

### 关于局域网访问的安全边界

用手机通过局域网访问时走的是普通 HTTP，**同一个 WiFi 下的其他人理论上能抓包看到你输入的密码**。
所以：

- 只在自家或信得过的 WiFi 下用手机访问；
- 在陌生网络里就用 `DaiganLauncher.exe --local` 只开本机；
- 后台对登录和保险箱解锁都做了失败限速（10 分钟内错 8 次就锁一段时间）。

### 调界面时怎么截图

零依赖，用的是系统里现成的 Edge + Node 自带的 WebSocket（不需要装 puppeteer）：

它自己会登录、等页面渲染好、再截图，常用参数：

| 参数 | 作用 |
| --- | --- |
| `--route /price` | 登录后停在哪个页面 |
| `--full` | 截整页（默认只截一屏） |

### B站比价的验证脚本

比价那一套没法进 `npm test`：它要联网、要 ffmpeg、要视觉后端、还要 `media-cookies` 里
有可用的 B站 登录态。所以单独两个脚本，**想验的时候手动跑**：

```bash
npm run test:bili          # 扫描链路 + 接口契约（用真实数据目录，只读地用它）
npm run test:bili-apply    # 写入路径（会真的改价格，但改的是副本）
```

两个都能加参数：`node scripts/bili-scan-check.mjs 原神 5`（游戏名 + 视频数）。

`test:bili` 检查的是**「用户能不能核对」这件事本身**：每条建议都得带来源视频、
来源帧、OCR 原文行、匹配分，多样本行的建议价必须落在样本区间里，
来源帧能取到真 JPEG，路径穿越被挡。

`test:bili-apply` 是唯一会写数据的，所以它先把真实库**复制一份**到
`data-bili-check-apply/` 再动手 —— 验证「写对了没有」不能拿真价格当小白鼠。
它证明四件事：建议价真的落进 `base_price` 且只落这一行；改派写的是目标项、
原匹配项一点没动；**阶梯价和增项不受影响**（只改基准价）；非法输入一律拒掉。
建大类也在这一份里验：真的落库、挂对游戏、重复建只报重名不多建、
不在扫描结果里的名字建不出来、**写完价之后大类候选还在**（`applyScan` 会重写
任务的 result，漏带 `sections` 就会把候选悄悄抹掉）。

两个脚本都自己起 sidecar（端口 **5419**，避开你正在用的 5410）和实例（端口随机），
跑完自己收摊，不需要先手工准备什么。唯一的坑是：如果上一次被强杀留下了
python.exe，5419 会被占着，脚本会明确告诉你结束掉它或换个端口。

**视频缓存的验证**（`data/bili-tmp/t-cache-scan.mjs`，临时脚本）连跑四次，
分别验冷启动、全部复用、强制重扫、一半命中。有个坑值得记下来：
**这个脚本第一版直接连跑三次做对比，结论是「缓存没让扫描变快」** ——
其实后两次都已经命中缓存了，40.3s vs 42.2s 是在比「两次都跑 AI」。
所以每次要测冷启动必须先 `DELETE FROM bili_video_cache`。
真正的对比是 **100.6s → 4.0s**。

**新游戏冷启动的验证**（`data/bili-tmp/t-cold-start.mjs` 和 `t-cold-api.mjs`，临时脚本）
也跑在库副本上。前者走函数、后者真起实例走 HTTP（16 项），验的是「建完之后
**同一批扫描行**能不能匹上」—— 这才是这个功能成不成立的判据。

两个坑记下来：

- **复制数据库要连 `-wal` / `-shm` 一起复制。** 只复制 `console.db` 会读到旧数据，
  最新的几次扫描还在 WAL 里没落盘。脚本报的任务比界面上看到的旧了三个小时，
  查了半天才发现是复制不全。（`scripts/lib/bili-check.mjs` 的 `copyRealData` 是对的，
  我自己另写的复制漏了。）
- **AI 会把 prompt 里的注释当成名字抄回来。** 第一版 prompt 写成
  `- 7.0版本主线（3 个视频）`，模型就老实把整行填进 `sources`，
  于是 63 条建议**一条都没建成**，而且没有任何报错 —— 只是「整理出来 0 条」。
  改成表格（`序号 | 名字 | 出现视频数`）之外，还加了一道防御性剥离，
  但**只剥「N 个视频」这一种**：`时与风（隐藏）` 这种真名字里也有括号，不能一起剥。

## 七、屏幕识别（记进度时自动读资源数字）

这一块的目标只有一句话：**别手抄游戏里的星声/体力/贝币/环石**，而且
**换分辨率也得认得出、数得准、换游戏也不用改代码**。

### 每个游戏一套配置（profile）

「认哪个游戏」是从**订单上那个游戏**来的（记进度那张表单按游戏分块，
每一块的「看画面」只认这个游戏的资源）。配置在 `shared/game-profiles.js`，
一个游戏一条：

| 游戏 | 图标宽 / 画面宽 | 模板文件 | 取数页 | 这条 profile 上的特殊开关 |
| --- | --- | --- | --- | --- |
| 鸣潮 | 0.0344 | `xingsheng.png` / `beibi.png` / `tili.png` | `B` 背包（星声、贝币）、`M` 地图（体力） | `layoutFallback`（按数字格式硬推的兜底，只对它成立） |
| 异环 | 0.0225 | `nte-jiayingbi.png` / `nte-fangsi.png` / `nte-huanshi.png` / `nte-dushi.png` / `nte-tili.png` | `B` 背包（甲硬币、方斯、环石）、`M` 地图（都市活力、体力） | `maskedNcc`（打分口径）、`clusterRatio`（锚点那一簇多宽）、两个资源 `allowZero` |

**图标大小必须按游戏分开算**，这是「任何分辨率都认得出」的前提：
游戏 UI 是按横向分辨率缩放的，所以「图标宽 ÷ 画面宽」是常数（实测鸣潮在
1152×720 到 3840×2400 十档都是 0.0344），但**两个游戏的这个常数不一样** ——
异环只有 0.0225（鸣潮的 65%）。拿鸣潮的比例去扫异环，档位整个偏掉，一个都找不到。
（也别换成「图标宽 ÷ 画面高」：16:10 与 21:9 下能差 43%。）

### 它是怎么认的

不看坐标，看**图标**。顶栏那几个资源图标是同一份美术资源，程序拿模板去对：

1. 先在画面上方那条带里找**最好认的那个图标**（鸣潮是星声、异环是甲硬币）当**锚点**；
   锚点的像素尺寸就是这一屏的缩放系数 —— 所以 1280 和 4K 用的是同一套逻辑，
   没有「y≈54 那一行」这种写死的坐标；
2. 其余图标只在锚点附近这一簇里找，**离锚点太远的候选一概不认**
   （实测界面左边有个亮块会被误认为贝币，然后读到隔壁星声的数字）；
3. 数字由 OCR 读，但**按几何关系把碎片拼回一个数**：
   OCR 会把 `2174` 切成 `21` + `74`、把 `129/2000` 切成四块，
   按「同一行 + 缝隙小」拼回去，再取图标右边最近的那一块；
4. **每个数字要认到两次以上（跨帧投票）才填进表单**。两次不一致就接着看，
   到时间还没凑够就留空 —— 认不准的时候它绝不硬凑一个数字。

#### 只找这一屏真会有的那几个（`keys`）

一屏只需要两三个资源，所以前端会把「这一屏有哪几个」一起发给识别。这不是省时间
的小优化，是修两个真问题：

- **锚点会挑错人**：异环的地图页只有都市活力和体力，但按「谁最像锚点」挑会挑中
  甲硬币 —— 那屏压根没有甲硬币，锚点定不出来，整条链路退化成一堆全条带搜索；
- **会认到隔壁**：那种退化状态下实机把体力的 `255` 挂到了甲硬币名下。

传了 `keys` 就只找这几个，锚点也从这几个里挑；不传还是老行为（整份模板表都找）。
`POST /api/ocr` 和 `/api/ocr/screen` 都收这个参数，服务端会先拿**这个游戏**的模板表
核一遍，塞别的游戏的 key 是无效的。

#### 异环那枚金币：为什么打分口径要按游戏分

异环的图标是「又亮又光滑」的画风。拿甲硬币（异环的锚点）举例，实机截图上传进
识别链路，模板和它**自己**匹配只有 **0.52 分** —— 把「模板」「真位置那块」
「命中那块」三张图并排放大看，肉眼一模一样。锚点分数不够，整屏就一个数都认不出来。

原因是打分函数的分母：分子只统计模板 core（亮的那部分）像素的起伏，分母却统计
**整个窗口**（含暗背景）相对**窗口均值**的起伏。图标又亮又光滑、内部几乎是
一整块渐变时，分子很小；而「图标 vs 背景」那点反差又把分母撑得很大 —— 于是
自己匹配自己也只有一半的分。

修法是让分子分母用**同一批 core 像素**（带掩码的 NCC）：分母换成 core 自己的
起伏，自己匹配自己严格等于 1，而且恒在 `[0,1]` 里，假阳性也一起压低。
代价是内层循环多 4 个累加器（实测慢约 1.6 倍），所以**按游戏开**
（`profile.maskedNcc`）：鸣潮那套阈值是按旧口径标定的，不动它就一点回归风险都没有。

同一个坑还带出另外两条：

- **锚点那一簇要按画面宽度算**，不能按「锚点图标宽的 6.5 倍」。鸣潮的图标是画面宽的
  3.44%，6.5 倍就是 22%，够用；异环只有 2.25%，6.5 倍只剩 14.6%，而它顶栏三个资源
  横跨 62%~86% 的画面宽 —— 最右边的环石直接落在簇外，锚点认出来了它却永远认不到。
  换算成比例之后鸣潮的数值和以前**完全一样**（6.5 × 0.0344 = 0.2236）。
- **锚点自己不要再扫一遍**：第一遍已经全条带找过它了，第二遍还按「其他图标」的
  逻辑又扫一次全条带，异环实测白花 4.5 秒。

实测（异环，2560×1600 的实机窗口）：甲硬币 1,008,984 ✓、方斯 4,208,820 ✓、
环石 3,147 ✓（分数 0.97 / 0.97 / 0.93）；地图页都市活力 `0/700` 取 0 ✓、
体力 `255/320` 取 255 ✓。同一套配置在 `shots/samples/nte-*.png` 上换四种分辨率
（1280×800 ~ 3840×2400）也全对。

> `0` 要能认出来是有意的：都市活力真的会显示 `0/700`，那个 0 是有意义的真值。
> 默认把 0 当噪声（界面上到处是 0，很容易配错），所以只有写明 `allowZero` 的资源
> 才收 0。斜杠那种「当前/上限」一律只取斜杠前面的当前值。

（早先给异环留过一条「是个 UE 窗口就猜是它」的兜底，知道真名之后就关掉了 ——

截屏这一步还有一条不显眼但致命的规矩：**截到的必须是游戏画面，而且跟 Windows 的

| 异环 · 装 RapidOCR-json | ~2.9s | ~1.0s |

一帧的预算写的是 1.5 秒，**定出锚点之后每个图标还保底给一点时间**（不给的话
会把贝币漏掉），所以最坏一帧会略超预算；热态那一列才是连点「看画面」时感受到的速度。

这一帧里**大头是图标匹配（冷 2.8s / 热 0.4s），OCR 只占 ~0.6s** ——
所以想再快，方向不是换 OCR，而是别每帧都重新找图标（跨帧记住标定 + 只认那几个数字块）。

> 能立刻看出哪一档、哪个游戏退化了。可以加 `--game=异环` 只跑一个游戏。

### 想认得更全，装一个本地 OCR 引擎（推荐，能一键装）

不装也能用（走 Windows 自带的 OCR），但**装了差距很大**：同一批截图，
自带 OCR 在超宽分辨率下会把 `2174` 读成 `21`，换上 PP-OCR 系的引擎之后
**鸣潮那十一种分辨率全对**（22/22，含 2560×1080 / 1920×822 / 3440×1440 这些超宽比例），
异环那两屏四种分辨率也全对（identify 自检一共 43/43）。

**怎么装：设置 → 屏幕识别 → 「Python 视觉后端」→ 点「一键安装依赖」。**
它会建一个项目内的 `data/vision-venv`（不动你系统里的 Python），装 RapidOCR + ONNX Runtime，
约 200MB，装完程序重启会自己起（也可以当场点「启动」）。模型**复用**仓库里已有的
`tools/ocr/rapidocr/models/`，不额外下载。界面上有进度、步骤和日志，
点「自检一下」是**真认一张图 + 真认一个数字块**，装错版本、缺 DLL 都会当场现原形。

装完回到 **设置 → 屏幕识别 → 重新检测**，它会告诉你现在用的是哪个。
六个引擎全都没有才会告诉你「用不了」，不会因为缺一个就罢工。

| 顺序 | 引擎 | 能不能一键装 | 说明 |
| --- | --- | --- | --- |
| 1 | **Python 视觉后端** | ✅ 能（推荐） | RapidOCR + ONNX Runtime，跑在项目内 `data/vision-venv` 里，长驻进程（127.0.0.1:5410）。有置信度，还能只认一个小数字块（13ms）。见 `integrations/screen-vision/README.md` |
| 2 | **Umi-OCR** | ✋ 要手动 | <https://github.com/hiroi-sora/Umi-OCR> 官方包是自解压 exe，装完还要在它自己的设置里打开「HTTP 服务」（默认端口 1224）—— 最后一步得你点，所以这里只给下载页 |
| 3 | **PaddleOCR-json** | ✅ 能 | 约 88MB 包 / 展开 250MB，**要 CPU 支持 AVX**（老机器可能跑不起来） |
| 4 | **RapidOCR-json** | ✅ 能 | 约 70MB 包 / 展开 95MB，**不需要 AVX** —— 不用 Python 的话，装这个最省事 |
| 5 | **Tesseract** | 自己装 | <https://github.com/UB-Mannheim/tesseract> 安装时勾上 `chi_sim` 中文语言包 |
| 6 | **Windows 自带 OCR** | 不用装 | 兜底，永远在 |

自动安装需要这台机器上有**能解 .7z 的解压器**（7-Zip / NanaZip 之类）。
设置页会先探测并告诉你有没有；没有的话它会说清楚，并给出下载页让你手动解压到
`tools\ocr\`。想装到别处也行 —— 每个引擎都支持用环境变量指路径
（`RAPIDOCR_JSON_BIN` / `PADDLEOCR_JSON_BIN` / `TESSERACT_BIN`）。

> 引擎都是**本机跑**的，截图不出这台电脑，和凭证保险箱一个立场。
> 装到 `tools/` 里的东西不进版本库（.gitignore 里排除了），换机器重新点一次就行。

#### 先把根因说清楚：目录的「完整性标签」会让程序整个降级

上面那些症状（`%TEMP%` 写不进去、`Add-Type` 报「拒绝访问」或
「A required privilege is not held by the client」、**「没有找到鸣潮游戏窗口」**）
在实测的那台机器上是**同一个根因**：

```powershell
icacls "D:\...\代肝价格查询"
#   Mandatory Label\Low Mandatory Level:(OI)(CI)(NW)      <-- 就是这一行
```

**Windows 的规则：进程的完整性级别 = min(父进程的级别, 可执行文件的标签级别)。**
这个项目目录被打上了 **Low 完整性标签**（带 `(OI)(CI)` 继承，所以目录里每个文件
都继承了 `(I) Low`），于是：

| 后果 | 表现 |
| --- | --- |
| 进程以 **Low** 运行 | 见下三行 |
| Low 写不进 Medium 的 `%TEMP%`（no-write-up） | 最初的 `EPERM: operation not permitted, open '...\Temp\xfc-....png'` |
| Low 环境里 `csc.exe` 起不来 / 编译被拦 | `Add-Type : 拒绝访问`，以及 `A required privilege is not held by the client` |
| **Low 看不见以管理员（High）身份运行的游戏** | `Get-Process` **静默丢掉**游戏进程 → 一个候选都没有 → 「没有找到鸣潮游戏窗口」 |

最后一条最容易骗人：**程序不是找不到窗口，是它根本看不见那个进程。**
`focus-game.ps1` 现在会自己查一遍完整性级别，报错时直接说清楚：

```
{"ok":false,"code":"game_window_missing","integrity":"low"}
```

界面上就会显示「本程序正以『低完整性』运行，看不到游戏进程……」，而不是让人去
反复确认游戏到底开没开。

**怎么修**（在**管理员**窗口里执行，两条命令，顺序不能反）：

```powershell
# 1. 把整棵树的 Low 换成 Medium —— 恢复 %TEMP% 写入和 C# 编译
icacls "D:\github_xm\代肝价格查询" /setintegritylevel (OI)(CI)Medium
# 2. 再把启动器单独标成 High —— 这一步之后进程才和游戏同级，才能激活它的窗口
icacls "D:\github_xm\代肝价格查询\DaiganLauncher.exe" /setintegritylevel High
```

然后**重启程序**（进程的级别在启动时就定死了，改标签不会影响已经在跑的进程）。

为什么要分两步：标签是**上限**而不是下限 —— 只做第 1 步的话进程变成 Medium，
写 `%TEMP%`、编译 C# 都正常了，但**还是激活不了管理员权限的游戏窗口**
（这正是「非管理员脚本唤不醒管理员窗口」那个老问题）。把 exe 标成 High 之后，
`min(父进程 High, 文件 High) = High`，和游戏同级。反过来从普通权限启动它，
`min(Medium, High) = Medium`，**不会越权提权** —— 这个方向是安全的。

> 第 1 步用 `Medium` 而不是「去掉标签」是因为 `icacls` 没有「删除标签」这个开关；
> 用 `SetNamedSecurityInfo` 把 SACL 置空可以真正去掉，但那要先启用
> `SeSecurityPrivilege`，不值得为一次修故障上这么重的手段。

#### 临时文件为什么不放系统临时目录

**因为 `%TEMP%` 不一定写得进去**（原因见上一节）。这是踩过的真实故障：程序在一个
受限环境里跑时，往 `%TEMP%` 写一个 2×2 的 PNG 直接被拒（`EPERM`），
「自检一下」整个接口 500 —— 而原因跟识别本身毫无关系。

所以临时文件的落点统一走 `src/util.mjs` 的 `scratchFile()`，**两档偏好、三档兜底**：

| 偏好 | ① 先放 | ② 写不进就退 | ③ 还不行才退 | 谁在用 |
| --- | --- | --- | --- | --- |
| `project`（默认） | `data/tmp` | 系统临时目录 | —— | 只被我们自己读的（Python 侧解图走 `np.fromfile`，中文路径没问题） |
| `ascii` | 系统临时目录（纯 ASCII） | **项目旁边的纯 ASCII 联接** `..\xfc-tmp` | `data/tmp` | **要给外部 exe 读写**的 |

#### 那个 `xfc-tmp` 联接是什么

外部 exe 读不了中文路径（实测同一个 exe、同一张图：ASCII 路径 `code:100` 正常，
项目路径 `code:300 JSON dump failed`），而项目目录本身就叫「代肝价格查询」，
Windows 的 8.3 短名也**不帮忙**（实测本项目短名是 `D:\GITHUB~1\代肝价~1`，中文原样保留）。
唯一的出路是让**路径前缀**变英文：程序会在项目**外面**建一个英文名的目录联接
（junction）指回 `data/tmp`，于是 `D:\github_xm\xfc-tmp\xxx.png` 就是纯 ASCII 的。

- 放在项目外面：只有前缀算数；放同一个盘：联接不能跨卷；
- 用 junction 而不是 symlink：junction 是 Windows 上唯一**普通用户就能建**的类型；
- **懒建**：只在系统临时目录真的写不进去时才建，正常情况下你看不到它；
- 建不出来（父目录也带中文 / 盘不支持 / 没权限）就退到 `data/tmp` ——
  那时只有 Python 后端能用。

实测：把 `TEMP` 指到一个不存在的盘，**旧引擎链（RapidOCR-json 那个 exe）照样 22/22**，
和正常环境一致 —— 这条路在加联接之前是走不通的。

同一个根因还会咬到**所有现场编译 C# 的 PowerShell 脚本**，而且多数是**静默**的
（`Add-Type -TypeDefinition` 要临时目录，`Add-Type -AssemblyName` 不要）：

| 脚本 | 编译失败时会发生什么 |
| --- | --- |
| `grab.ps1` | DPI 那步被 catch 成 `dpi=failed` → **静默截出缩放错的图**（2560×1600 截成 1707×1067）→ 之后所有识别全错 |
| `focus-game.ps1` | 直接**死在编译那一步**，游戏窗口没被激活 → 截到的是别的窗口 |
| `game-key.ps1` | 同样死在编译那一步，**按键发不出去** |
| `screen-info.ps1` | 什么都不输出 → 自检里「截屏是不是被 DPI 虚拟化了」那道**防线静默失效** |

#### 所以现在根本不编译了：改成加载预编译程序集

一开始的修法是给这四个脚本加临时目录守卫（`lib/ensure-tmp.ps1`）。**但守卫不够**：
实测有机器上临时目录**明摆着可写**（守卫的写入探测通过了），`Add-Type` 还是失败，
而且前后给出两个不同的错：

```
Add-Type : 拒绝访问
Add-Type : A required privilege is not held by the client     ← Win32 1314
```

说明问题不在临时目录，而在「现场编译」这件事本身（要拉起 `csc.exe`，在某些环境里被拦）。
于是改成：**把 P/Invoke 声明编成一个 5KB 的程序集 `scripts/lib/XfcWin32.dll` 提交进仓库**
（源码是 `scripts/lib/xfc-win32.cs`，改动后用 `lib/build-win32-dll.ps1` 重建，两个都要提交），
四个脚本开头只写：

```powershell
. "$PSScriptRoot\lib\win32.ps1"
[void](Import-XfcWin32)
```

加载程序集**不需要编译器、不需要临时目录、不需要任何特权**，所以这一类故障被整体消掉了，
顺带每次调用省掉约 140ms（实测干净进程：现场编译 254-281ms，加载 dll 117-129ms）——
而 `focus-game.ps1` 每次识别前都要跑一次。没有 dll 时（只拿了源码）才回落到现场编译，
那条路才需要 `lib/ensure-tmp.ps1` 的守卫。

**注意一个坑：加载这个 dll 不能用 `Add-Type -Path`**（它内部是 `Assembly.LoadFrom`，
会把路径拼成 `file://` URI，而本项目路径带中文 → URI 非法 → `COR_E_FILELOAD` 0x80131515
「Operation is not supported」，程序集本身完全没问题：拷到纯 ASCII 路径就能加载）。
所以 `lib/win32.ps1` 用的是 `[Reflection.Assembly]::Load([IO.File]::ReadAllBytes($dll))` ——
**读字节数组，全程不碰 URI，任何路径都能用**。这也是为什么这个项目里
「路径带中文」这件事会反复咬人：外部 exe 读不了、`LoadFrom` 也读不了。

修完的实测：把 `TEMP` 指到一个不存在的盘，这四个脚本的输出与正常环境**逐字一致** ——
`focus-game.ps1` 照样找到并激活 `鸣潮`、`game-key.ps1` 照样走到焦点判断、
`screen-info.ps1` 照样报 `2560 x 1600`、`grab.ps1` 照样 `dpi=per-monitor-v2`；
自检报「截到 2560x1600，物理屏 2560x1600 —— 整屏，DPI 感知正常」，十一种分辨率 22/22。
而且这次不依赖 `%TEMP%` 是否可写，也不依赖能不能编译 —— 两条路都不需要了。

**注意 `scripts/*.ps1` 全部保持纯 ASCII、不带 BOM** —— Windows PowerShell 5.1 会把
无 BOM 的 .ps1 按 GBK 读，写中文注释会直接把脚本解析坏（`grab.ps1` 就这么坏过一次，
报的是 `Unexpected token '}'`）。这一条对所有 .ps1 都适用。

### 图标变了怎么办（换了游戏版本）

游戏大版本更新、把顶栏图标重画了，认不出来是正常的。设置 →
屏幕识别 → **自备一个图标模板**：给它一张顶栏截图 + 图标本体所在的方框
（x / y / 宽 / 高），程序当场把那个图标抠出来存进 `data/resource-icons/`，
以后优先用你这份（不动程序自带的）。

**文件名要对上 profile**：识别的模板是按文件名找的，异环那套带 `nte-` 前缀
（`nte-jiayingbi.png` 这种）。自备模板时先在上面把「游戏」选对，文件名就会带上
对应的前缀，不会出现「异环的体力把鸣潮的体力模板顶掉」这种事 ——
两个游戏的「体力」本来就是两张不同的卡。

### 技术上的取舍（几句话）

算法在 `src/vision.mjs`：**积分图版 NCC 模板匹配**（OpenCV `matchTemplate` 的
`TM_CCOEFF_NORMED` 口径 + scikit-image 的工程形式）配上**由粗到细的多尺度搜索**，
外加**锚点定标 + 相对布局**（思路来自 Airtest 的 `record_pos` / `resolution`）。
一个第三方库都没引 —— 这是照着思路自己写的实现，不是搬代码。

「哪个游戏、哪几个资源」全部来自 `shared/game-profiles.js` 的 profile：
图标大小比例、模板文件名、取数页与按键、锚点、`allowZero`、打分口径、
锚点簇的宽度都是它的字段。加一个游戏 = 加一条 profile + 几张模板图，
`src/screen.mjs` / `src/routes/` 一行都不用改。

之所以非要换掉老实现：老的每匹配一个位置都要重算窗口均值方差，
2559 宽的顶栏上光一次匹配就要 **21 秒**；现在同场景几十毫秒。
评估和踩坑记录都写在 `PORT-CANDIDATES.md` 里。

## 八、常见问题

**Windows 怎么启动、停止或重启？**
双击 `DaiganLauncher.exe`，在控制台里使用对应按钮；也可以直接带参数启动。
启动器会自动寻找 Node.js，并把日志写入 `launcher-data/server.log`。

**窗口一闪就没了 / 提示需要 Node.js？**
说明这台电脑上没找到 Node.js。去 <https://nodejs.org> 下载 LTS 版本装上。
如果刚装完还是提示找不到，**关掉窗口重新开一个新的**——PATH 的改动只对新开的窗口生效。

**点「生成图片」没反应 / 下载文件夹里没东西？**
浏览器可能把「连续下载多个文件」拦掉了。导出范围改成「全部游戏合并成一份」就只下一个文件；
或者允许这个网站「下载多个文件」再试。图片也可以用 Chrome / Edge / Safari 打开后台来生成。

**生成 Word 文档打不开？**
它是标准的 `.docx`，Word 和 WPS 都能开。如果被手机当成未知文件，先存下来再用 WPS 打开。

**Excel 表格里的价格为什么不是「¥70 / 30天」这种文本？**
单价单独一列存的是**数字**（显示成 `¥70.00`），这样才能排序、求和、做透视表。
带单位和档位的信息在「单位」「起订」「档位」三列里，一眼也能对上。

**提示端口被占用？**
换一个端口：`DaiganLauncher.exe --port 8888`。

**手机打不开那个局域网网址？**
确认手机和电脑连的是同一个 WiFi；Windows 防火墙第一次会弹窗，要选「允许访问」；
公司/学校网络常常禁止设备之间互访，那种网络下手机连不上是正常的。

**屏幕识别认不出来 / 认错了？**
按这几步看：

1. **先去 设置 → 屏幕识别 看它用的是哪个引擎。** 只有「Windows 自带 OCR」的话，
   在「Python 视觉后端」里点 **「一键安装依赖」**（约 200MB，需要这台机器上有 Python 3）——
   实测装完之后十一种分辨率全对，而自带 OCR 在超宽分辨率下会把 `2174` 读成 `21`。
   不想装 Python 也行：在「安装选项」里装 **RapidOCR-json**（约 70MB，不需要 AVX），
   结果一样（两个后端对照过，都是 22/22）。
2. **看提示里有没有「字太小，务必核对」。** 有这句说明当前是自带 OCR 且顶栏文字
   不到 26px 高（超宽分辨率下常见），对着游戏核一遍；装了上面那个引擎就不会再提示。
3. **换了游戏大版本、图标重画了？** 设置 → 屏幕识别 → 自备一个图标模板，
   给一张顶栏截图 + 图标所在的方框（x/y/宽/高），它会当场抠出来存下。
4. **一个数字都认不出来（连「没配上数字的」都没有）？** 那是截屏这一层的问题，
   不是识别的阈值问题：跑 `node scripts/vision-selftest.mjs`，第一条「截屏自检」
   会直接告诉你截到的是不是整屏（显示器缩放不是 100% 时最容易踩这个）。
5. **「Python 视觉后端」那张卡说「起来了但没就绪」/「依赖没装」？** 点「看日志」，
   它自己的 stderr 就在里面（载模型失败、缺 DLL、模型没找齐都会写在那儿）。
   点「自检一下」会真认一张图 —— 通过就说明能用，不用管状态字。
6. **说「5410 端口上已经有一个视觉进程，但 token 对不上」？** 那是上次程序被强杀时
   留下的 python.exe 还占着端口。正常情况下它会跟着主程序一起退（主程序一死，
   管道断开它就自己退出）；真留下了就在任务管理器里结束那个 python.exe。

想自己确认「换分辨率还认不认得出」，跑 `node scripts/vision-selftest.mjs`；
想比较两个后端，跑 `node scripts/vision-parity.mjs`。

**忘了登录密码？**
关掉启动窗口，然后：

```bash
node scripts/reset-password.mjs            # 清掉密码，下次启动回到初始化引导
node scripts/reset-password.mjs 新密码      # 或者直接设一个新密码
```

只会动登录密码，**游戏、价格表、客户、订单、订单凭证一概不碰**。
保险箱密码是另一套，不受影响（所以更要记住保险箱密码——那个没有后门）。

**价格表里为什么不能直接建服务项？**
因为结构是「游戏（一张价格表）→ 大类 → 服务项」。先在大类行上点「加服务项」，或者先「新建大类」。没绑游戏的大类会归到「通用」组里。

**换了台电脑，凭证打不开？**
备份文件里的凭证是密文，必须用**同一套保险箱密码**才能解开。
换了密码就不行了。

**想只在自己电脑上用？** 用 `DaiganLauncher.exe --local` / `./start.sh --local`。

## 九、技术上的事

- **本地优先**：后端保持 `node:http` + `node:sqlite` + `node:crypto`，前端构建依赖锁在 `package-lock.json`。
- 前端入口是 React 19 + Vite 8，页面和表单已经全部收敛到 React，统一使用 Lucide React 图标。
- 界面从「React 壳 + 旧命令式视图」搬到单栈的过程和现状，见下面「界面是怎么从旧栈搬到 React 的」。
- 密码用 scrypt 哈希；会话是 HttpOnly + SameSite=Lax 的 Cookie，有效期 14 天。
- 数据库开了 WAL 和外键约束；迁移按 `PRAGMA user_version` 顺序前进，只增不改。
- **钱的算法只有一份**：阶梯价规则在 `shared/pricing.js`，服务端（`src/pricing.mjs`）、
  React 组合报价弹窗和旧价格表页面（现在只当测试参照物）都调它。以前服务端和前端各有一份
  实现，一旦漂移就会「客户看到的价」和「实际收的价」对不上，而且很难发现。
- 订单口径（阶梯单价、日体、可得、进度、收款）同理，只有一份：`shared/order-calc.js`。
- **订单上的游戏是推出来的，不是存的**：下单时按明细里的服务项所在的游戏推
  （服务项自己的 `game_id` 优先，没有就看它大类属于哪个游戏）。一个游戏就写它，
  多个就拼成 `A + B` 并把 `game_id` 留空；混单的资源/进度按 `【游戏】` 分段存，
  只有一段时不加标记，所以老记录、老报表一个字都不用改。
- 附 `PRODUCT.md` 和 `DESIGN.md`：前者是产品定义，后者是视觉与交互的规则书。

### 界面是怎么从旧栈搬到 React 的

壳层（导航、主题、路由、顶栏、侧边栏）是 React，八个业务页一页页搬完了，
**每搬一页就连那一页的表单、抽屉一起搬**，否则还是半吊子。顺序是按依赖从叶子往根：

```
游戏 → 客户 → 价格表 → 订单 → 财务 → 报价单 → 保险箱 → 设置 → 客户档案详情
```

**现在全部搬完了**，一页不剩。挑几件值得单独说的：

- **游戏表单**（`client/game-form.jsx`）—— 第一个全 React 的表单；
- **客户表单**（`client/customer-form.jsx`）—— 字段和提示跟旧的一字不差；
- **确认框**（`client/app/confirm.jsx`）—— 各页原先弹的都是旧 DOM 对话框，
  现在换成 React 渲染的，调用方式（`if (!await confirmDelete({...})) return`）一字未改；
- **价格表整页**（`client/price.jsx` + 五个浮层模块）—— 大类表单、组合报价、
  服务项表单、阶梯价编辑器、套餐增项编辑器、服务项详情抽屉、导出器，全部换成 React；
- **提示条**（`client/app/toast-store.js` + `client/app/toast.jsx`）—— 全站唯一一份
  toast 实现：谁都能 `toast()`，由 `<ToastHost />` 统一画，样式和时长不会再各走各的；
- **订单整页**（`client/order-composer.jsx` + `client/order-detail.jsx`）—— 开单台
  （挑服务、算钱、自动到期日、改明细）和订单详情（记进度、记收款、推进状态、
  分享进度、拆单、删单）都换成 React，`/orders`、`/orders/new`、`/orders/:id`
  三条路由全走 React；
- **报价单**（`client/quote-composer.jsx`）—— 做报价单/改报价单的抽屉，以及
  列表里那个「看文字版」弹窗（以前是旧 `modal`），一起换成 React；
- **保险箱**（`client/vault.jsx` + `client/vault-gate.jsx`）—— 凭证列表、登记/改
  凭证表单、明文取用弹窗、审计抽屉、解锁门禁（`promptUnlock` /
  `ensureVaultReady`）全部 React。门禁的**状态**仍然只有一份：
  `public/js/vaultgate.js` 里的 `vaultState` + `syncVault` + 监听器，设置页和
  保险箱页看到的是同一个真相；
- **设置整页**（`client/settings.jsx`）—— 店铺信息、改登录密码、改保险箱密码、
  屏幕识别（引擎列表 + Python 视觉后端那张卡 + 自动安装 + 进度轮询）、自备图标模板、
  导出/导入备份、清空数据，连同四个抽屉表单一起搬；
- **客户档案详情**（`client/customer-detail.jsx`）—— 客户名下的订单（在做/已结束
  各自封顶 + 「还有 N 张」）、收款流水、联系方式、账目、凭证脱敏列表，以及
  「归档 / 彻底删除」那个三选一（旧 `choiceDialog` 的 React 版）。

价格表这一页值得单独说一句：它的浮层是**互相叠**的 —— 服务项详情抽屉上点「阶梯价」
会再开一层，阶梯价里点「加一档」再开一层，删服务项时确认框又叠在抽屉上。
所以 `client/app/overlay-host.jsx` 从「一次只开一个」改成了**一叠**（每层各自一个
原生 `<dialog>`，浏览器管 top layer，Esc 只关最上面那层），滚动锁也交给宿主统一管
（里层关掉不能把外层的锁也解了）。防连点靠 key：同一把 key 已经在最上面就先关掉再开。

**旧栈已经清零**：`public/js/views/` 那一整批命令式视图（`price.js` / `orders.js` /
`orderbits.js` / `settings.js` …约 6000 行）、`client/lib/legacy-features.js`、
`client/lib/legacy-ui.js`、`public/js/ui.js`、`public/js/dom.js` 全删了。
`main.jsx` 里不再有 `view:` 适配器、`setActions` 管线和 `vaultgate` 传参；
认不出来的地址走 `client/app/not-found.jsx`（以前会偷偷退回总览）。
`public/js/` 现在只剩三个真正被 React 调用的文件：`pricecard.js`（画价格表图片）、
`progresscard.js`（画进度卡）、`vaultgate.js`（保险箱状态，只剩状态没有界面 ——
弹窗都在 `client/vault-gate.jsx`）。
`public/dist/` 也从版本库里拿出来了（`.gitignore` 里有一条）：`npm start` 的
`prestart` 会自动 build，不必再把 1.2MB 的产物提交进 git。

新表单照着这四块写：

- `client/app/overlay-host.jsx` —— 让 React 浮层能被命令式打开：
  `const saved = await openGameForm()`，取消得到 `null`，调用方式和旧的
  `formDrawer` 完全一样，所以页面代码几乎不用改；
- `client/app/drawer.jsx` / `client/app/modal.jsx` —— 抽屉和对话框本体。
  刻意沿用旧类名（`dialog.drawer` / `.drawer__head` / `.drawer__foot` /
  `dialog.modal` / `.modal__foot`），因为 `client/styles.css` 直接 `@import` 了
  `public/css/app.css`，样式能继承，迁移期间新旧浮层长得一模一样，不会出现视觉断层；
- `client/app/fields.jsx` —— 受控字段：文本、多行、下拉、逗号分隔（区服/标签）、
  勾选框、图片上传。同样沿用 `.field` / `.lbl` / `.inp` / `.ta` / `.sel` / `.err`；
- `client/app/confirm.jsx` —— 确认框（`confirmDialog` / `confirmDelete`）；
- `client/app/copy-button.jsx` —— 「复制价款」这类复制按钮。

**怎么确认「搬完长得一样」**：搬一页的时候，`npm run test:ui` 会把新旧两个表单在同一个
浏览器里各开一次，量出抽屉宽度、字段顺序、半宽/整宽、控件类型、每个字段的宽度、页脚按钮，
逐项对比（差 1px 以上就算不一致）。这比截图目测可靠 —— 结构和类名悄悄变了会当场红。

这一步真抓到过东西：旧引擎对自定义字段会补一个 `field--full`（`ui.js` 里
`if (f.width !== 'half') node.classList.add('field--full')`），漏掉它两个下拉就会
挤进网格的一列里 —— 光看代码看不出来，量宽度 358 vs 173 一眼就看出来了。

旧实现删干净之后就没得对比了，改用 `checkFormShape()`：把那一页表单的**金标准形状**
（标题、宽窄、字段顺序与半宽/整宽、控件类型、页脚按钮）写死在测试里，以后谁把字段挪走、
加宽、换个控件类型，当场红。现在**每一页都是这么盯的** —— 结构照样是量出来的，
只是参照物从「旧实现」换成了「上一次认可的结构」。

`npm run test:ui` 里还有几段是「这一页独有的钱」：组合报价的合计和复制出去的报价单格式、
阶梯价改动有没有落库、导出图片/Word/Excel 的文件名（把 `<a download>` 的点击截下来看，
不真往磁盘写）、财务页八个格子对不对得上接口。另外那些「不该漏的东西」也在里面：
订单详情记完收款要能对上 `已收`、删完要剩几笔，保险箱锁着的时候明文一个字都不能出现在
列表里，客户档案上点一张单要能进订单详情，乱敲地址要落到兜底页。

屏幕识别（OCR）这块测得到的是「状态能取到、契约不破」：后端快照在不在、引擎链顺序对不对、
依赖清单文件在位不在位、自检要么通过要么给得出能照做的原因（测试实例的 venv 在临时数据目录里，
所以多半走的是「给原因」那条路），以及装依赖/自检那几条路不会 500。
「装了引擎之后真的认得出」这件事得在装了引擎的机器上验 —— 用
`node scripts/vision-selftest.mjs` 和 `node scripts/vision-parity.mjs`。
